# T3 Research Upgrade

Use the current T3 implementation and a reproduced failure to choose the change. Existing research starts in `docs/internals/aigithubnews-execution-schedule-2026-10-23.md`; inspect the relevant saved source rather than loading the full catalog. A stored README, a selected candidate, a passing local experiment and an operating deployment are different results.

Pin code evidence to a full commit and capture time; record the installed package version for documentation. Preserve the original URL and distinguish statements made by a project from behavior reproduced here. Check changed upstream facts before relying on a saved snapshot.

For retrieval changes, reuse `apps/server/scripts/evaluate-knowledge.ts` and keep the dataset hash, mode, embedding model and vector cache comparable. Preserve required user instructions and source references. Report prompt token estimates separately from provider billing and generated-answer accuracy. Investigate latency regressions with alternating comparisons; one faster run does not establish a speedup.

For long-work recovery, preserve native session and message identities. A checkout or requirement change does not resolve unknown delivery. Wait for receipts or worker drains in tests. Verify duplicate dispatch, accepted input, cancellation, late output and usage accounting on the affected path.

For a skill correction, record the observed failure, original skill hash, candidate hash, relevant source/version, focused check and remaining limits. Retain the exact original for rollback. Apply only the improvement supported by the evidence; leave unrelated skill policy and current app choices intact.
