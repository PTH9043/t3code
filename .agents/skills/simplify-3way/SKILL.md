# 3-Way Simplify & Code Hygiene Review

현재 변경분(`git diff` 또는 지정 파일)을 3개의 독립된 관점으로 병렬 검토하고, 검증된 개선점만 최소 범위로 안전하게 반영합니다.

## 적용 원칙

- **동작 무변경(Behavior-Preserving)**: 요청받지 않은 기능 변경·대규모 리팩터링·미이해 주석 삭제를 금지합니다.
- **증거 기반**: 모든 지적은 `file:line`과 구체적 근거를 포함해야 합니다. 근거 없는 스타일 취향 지적은 폐기합니다.
- **근접 중복 제거**: 서로 다른 관점이 같은 파일의 ±3줄 이내를 지적하면 하나로 병합하고 더 높은 심각도를 채택합니다.

## 1단계: 검토 대상 수집

1. 인자로 대상 파일이 주어지면 해당 파일만, 주어지지 않으면 `git diff --stat` / `git diff`의 변경 파일을 대상으로 삼습니다.
2. 변경 파일이 0개이면 즉시 중단하고 보고합니다.

## 2단계: 3-Way 병렬 리뷰 실행

가능하면 T3 호스트 `workspace_delegate(action: "run_parallel")` 또는 서브에이전트로 아래 3명의 읽기 전용 리뷰어를 **병렬 실행**합니다. 단일 에이전트 환경이면 3개 체크리스트를 순서대로 독립 수행합니다.

1. **관점 A — Reuse & Duplication (재사용·중복)**
   - 방금 추가한 로직이 `packages/shared`, `packages/contracts`, 기존 유틸리티에 이미 존재하는지 확인합니다.
   - 같은 파일/모듈 내 복붙된 분기나 불필요한 래퍼 함수를 찾습니다.
2. **관점 B — Clarity & Scope Discipline (명확성·과잉설계 차단)**
   - 과도한 추상화, 1회용 어댑터, 죽은 코드(dead code), 불필요한 방어 분기를 식별합니다.
   - 타입 안전성(`any` 남용, Effect 오류 채널에 untagged error 유입 등) 위반을 점검합니다.
   - Ponytail 규율에 따라 변경된 diff에 새로 추가·잔존한 `// shortcut:` 기술 부채 주석을 집계하고, Never-Cut 안전 경계를 침범한 지름길이 없는지 확인합니다.
3. **관점 C — Efficiency & Production Safety (효율성·운영 안전성)**
   - 불필요한 반복 I/O, O(N^2) 루프, 무제한 메모리/버퍼 축적, WebSocket 과대 페이로드, 고주사율 GPU 스파이크 유발 CSS 애니메이션을 찾습니다.
   - Windows 경로/인코딩, 리소스 정리(파일 핸들·타이머·프록시 서버 종료), 누락된 null/경계 검사를 확인합니다.

## 3단계: 중복 병합 및 필터링

- 3개 관점 결과를 모아 동일 파일 ±3줄 이내 겹치는 항목은 하나로 합칩니다.
- `high` / `medium` 실효성 있는 항목만 선별하고, 단순 취향(`nit`)이나 동작 위험이 큰 구조 개편은 제외합니다.

## 4단계: 최소 수정 및 검증

1. 선별된 항목만 최소 diff로 수정합니다.
2. 수정 범위에 해당하는 타깃 테스트(`vp test run <files>` 또는 `vitest run`)와 타입 체크(`tsgo --noEmit`)를 실행해 **전부 통과**함을 확인합니다.
3. 변경 요약(수정된 파일·항목, 보류/제외한 항목, 변경 diff 내 `// shortcut:` 부채 집계, 검증 명령과 결과)을 간결하게 보고합니다.
