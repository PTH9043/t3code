# T3 AI Workflow 구현·운영 반영 상태

2026-10-26부터 2026-10-27까지의 작업 기록이다. [개발 계획](t3-ai-workflow-development-plan-2026-10-26.md)과 [스킬 분석](t3-workflow-skills-analysis-2026-10-26.md)의 제안, 실제 후보 구현, 운영 반영을 구분한다. 기본 워크플로는 분리 앱에서 수정·검증한 뒤 운영 프로그램으로 교체했다.

## 사용자에게 확인한 조건

사용자는 “제안한 기존 제한·이벤트 경로로 진행 → 어떻게 바꿀지는 내가 써보면서 이야기할께 계속해라”라고 답했다. 이에 따라 작성 노드 24개, 기존 병렬 폭 6, 기존 단계 시도 상한 10과 기존 명령→이벤트→프로젝션 경로를 유지한다. 입력 수나 스킬 수의 새 상한은 추가하지 않는다.

현재 요청의 권한·질문하기·조건 확인·계획 모드와 참가자 선택을 유지한다. 새 범위와 조건은 사용자 답변 전에 운영에 적용하지 않는다. 아래 구현 선택이나 테스트 설정을 사용자 승인 조건으로 기록하지 않는다.

사용자는 이어서 “기본 기능을 교체하고 화면 검증해 헤드리스 브라우저로”라고 지시했다. 이 답변에 따라 기본 워크플로를 먼저 운영에 반영하고 headless 화면 검증을 수행했다. 예약 연동과 앱 안의 AI 초안 생성까지 완료했다는 의미로 확대하지 않는다.

## 운영에 반영한 수정

| 항목                  | 확인한 결과                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 연결 끊김·SQLite 조회 | 앞선 분리 검증 후 운영 반영. 종류별 활동 조회가 큰 테이블을 반복 탐색하던 경로에 기존 인덱스를 사용한다. DB 손상으로 판정하지 않았으며 읽기 전용 무결성 검사와 조회 비교를 수행했다. |
| 평가 CLI 타입 오류    | 별도 후보에서 수정·타입 검사·동일 평가 입력 비교 후 소스 반영. 평가 기준·모델·예산은 변경하지 않았다.                                                                                |
| Codex 질문 카드       | Codex 0.164의 비동기 질문 메타데이터를 기존 생성 스키마가 버리던 문제를 수정했다. 선택지 없는 질문도 카드로 전달하고 같은 native 대화에서 답변을 이어간다.                           |
| 답변 중복·전달 불명   | 답변을 제출하기 전에 중복 제출을 차단한다. 수락된 같은 답변은 재전송하지 않으며, 전달 결과가 불명확하면 재전송을 막는다. 제공자에 의해 닫힌 질문과 사용자 답변을 구분한다.           |
| 협업 질문 대기        | 질문만 남기고 native turn이 끝난 경우 협업 단계를 완료 처리하지 않는다. 답변과 후속 완료의 도착 순서가 바뀌는 경우도 검사했다.                                                       |

질문 수정은 `D:/__NewAutoUsage-connection-20261026`의 분리 앱에서 검증한 뒤 20개 파일을 운영 소스로 반영했다. 집중 테스트 155개, 서버·웹·모바일·Codex 연결 라이브러리 타입 검사와 변경 파일 린트가 통과했다. 실제 Codex의 자유 입력 질문→답변 전송→후속 답변 결과를 확인했다. 기존 생성 디코더와 후보에 같은 native·합성 알림 4건을 넣은 비교도 기록했다.

운영 데이터 홈은 `E:/NewAutoUsage`다. 기존 프로젝트·대화·메시지·지식 항목의 누락이 없고, 기존 대화의 권한·계획 모드와 설정 파일 해시가 유지됐다. 운영 웹 5733과 백엔드 13773의 HTTP 200, 실제 데스크톱 창의 표시·렌더링, 실행기·백엔드·데스크톱의 High 토큰을 확인했다. 창은 기존 `showInactive()` 경로로 표시했고 포커스를 가져오지 않았다. 초기 Codex 상태 조회의 10초 경고는 상태 재조회 후 `ready`, 0.164.0으로 확인됐다. 시간 제한을 늘리거나 모델·계정을 바꾸지 않았다.

질문 수정의 근거와 복구 원본은 `.t3/question-cards-20261026/RESULT.json`, `evidence.json`, `production-data-proof.json`, `production-visible-proof.json`, `production-token-proof.json`에 있다. 이는 이번 운영 검증의 기록이며 모든 세션이나 미래 실행의 성공을 보장하는 의미는 아니다.

## 운영에 교체한 기본 워크플로

후보는 `D:/__NewAutoUsage-workflow-20261026`, 격리 데이터는 그 안의 `.t3/workflow-app`이다. 운영 데이터나 테스트 설정을 서로 복사해 적용하지 않는다. 테스트 앱은 숨김 상태로 유지한다.

| 기능        | 운영 반영 범위                                                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 템플릿 | 기능 개발·오류 수정·조사·검토·워크플로 작성·스킬 비교 6종                                                                                          |
| 정의·입력   | 저장 버전 고정, revision 충돌 검사, 복제·보관·보관 해제, JSON 가져오기·내보내기, 입력 검사·리터럴 치환                                             |
| 실행·저장   | 기존 명령·이벤트·프로젝션과 협업 executor를 사용. 같은 시작 요청 중복 방지와 역할·정책 스냅샷                                                      |
| 제어·복구   | 신규 단계 배정을 멈추는 일시정지·재개·취소·허용된 실패 단계 재시도. 전달 불명 재제출 차단, 이전 시도의 늦은 결과로 새 실행 상태를 덮지 못하게 처리 |
| 스킬        | 파일 메타데이터·호출 제한·호환성 검사, 본문·참조·스크립트·자산 manifest 고정. native와 지침 전달 구분                                              |
| 웹·데스크톱 | 단계 양식과 같은 편집 상태를 사용하는 지연 로딩 캔버스, 저장·입력·실행 제어                                                                        |
| 모바일      | 저장 템플릿 실행·입력과 실행 제어. 편집기는 웹·데스크톱에 제공                                                                                     |
| 응답 크기   | 실행 목록에는 요약만 조회하고 선택한 실행의 상세 그래프·결과를 따로 조회                                                                           |

후보에서 15개 파일의 집중 테스트 258개와 서버·웹·모바일·Codex 연결 라이브러리 타입 검사가 통과했다. 실제 앱 RPC에서 6종 템플릿 저장·미리보기·같은 요청의 중복 시작·일시정지·재개·취소·오래된 revision 거부를 검사했다. 완료를 기다리는 테스트는 receipt·drain·Deferred를 사용한다.

사용자가 승인한 Chrome headless 검증 17개가 통과했다. 저장·복제·버전·스킬 연결·캔버스와 폼·잘못된 입력·JSON·보관 해제·좁은 웹 화면·실제 실행 제어를 확인했다. 실제 Codex의 선택지 없는 질문 카드에 화면에서 답변하고 후속 응답을 확인했다. 직접 실행과 질문하기 실행 모두 선택한 역할·권한·계획 모드를 유지하고 취소 완료 상태에 도달했다.

화면 검사에서 저장 후 실행 입력이 지워지는 문제, 입력 이름을 비우면 편집 화면이 깨지는 문제, 같은 ID의 JSON을 불러온 뒤 저장 revision이 누락되는 문제를 찾아 수정했다. 이 수정 후 편집기 회귀 테스트 5개와 웹 타입 검사·변경 파일 린트, 실제 headless 흐름을 다시 통과했다. 앞선 258개 전체를 이 웹 수정 뒤에 다시 실행한 것으로 기록하지 않는다.

Codex 0.164는 고정 경로를 `skills/extraRoots/set`에 등록하고 실제 native 목록의 이름·경로·활성 상태를 확인한 뒤 skill 입력으로 전달한다. 명령·브라우저·추가 작업자 도구를 끈 native 검증에서 스킬 원문에만 있는 결과를 확인했다. Claude SDK 0.3.251은 고정한 local plugin의 스킬이 전체 digest 이름으로 초기화 목록에 등록되는 것을 확인했다. 이 관측을 모든 운영 실행에서 스킬이 실제 사용됐다는 주장으로 확대하지 않는다. 지원하지 않는 native 확장을 지침 방식으로 조용히 대체하지 않는다.

2026-10-27 00:58 KST에 변경 파일 49개를 운영 소스로 교체했다. 앞서 반영한 SQLite·평가 CLI·질문 수정도 유지했다. 운영 앱의 정상 시작으로 마이그레이션 77·78과 워크플로 저장 컬럼·프로젝션 3종·요약 조회 인덱스가 적용됐다. 운영 API에서 기본 템플릿 6종을 조회하고, 교체된 운영 웹을 별도 headless 브라우저로 열어 템플릿과 편집기가 정상 렌더링되는 것을 확인했다. 운영에 테스트 워크플로나 실행을 만들지 않았다.

교체 전 운영 서버를 종료한 상태에서 읽기 전용 `VACUUM INTO`로 일관된 DB 백업을 만들었다. 백업은 9,934,110,720바이트이며 SHA-256은 `11172c755de518670ef2790be8367cd42fa4582c477e53ee4f8df5b6f81e4adc`다. 정확한 기존 소스 원본과 백업 정보는 `.t3/workflow-upgrade-20261026/production-before-source/`, `production-db-backup.json`에 있다.

데이터 홈 `E:/NewAutoUsage`와 기존 프로젝트 19개·대화 111개·메시지·지식 항목의 ID가 보존됐다. 기존 대화의 권한·계획 모드와 설정 해시도 유지됐다. 웹 5733·백엔드 13773은 HTTP 200이며 실행기·백엔드·실제 Electron 창의 High 토큰을 확인했다. 창은 `showInactive()`로 보이게 표시됐고 포커스를 가져오지 않았다. 수동 화면 조작 없이 창 이미지를 읽어 렌더링과 초기 연결 중 표시의 해제를 확인했다. Codex 0.164.0은 운영 API에서 `ready`다. 기존 Gemini 계정 지원 오류는 별도 상태이며 이번 교체로 해결했다고 기록하지 않는다.

검증·교체 결과는 `.t3/workflow-upgrade-20261026/RESULT.json`, `evidence.json`, `headless-report.json`, `headless-api-result.json`, `production-data-proof.json`, `production-schema-proof.json`, `production-api-proof.json`, `production-headless-proof.json`, `production-visible-proof.json`, `production-token-proof.json`에 있다. 사용 방법은 [AI 워크플로](../user/workflows.md)에 정리했다.

## 후속 범위와 검증 한계

- 예약 실행이 특정 워크플로 버전을 참조하는 연결과 앱 안에서 AI가 초안을 생성하는 기능은 미구현이다. JSON 초안 가져오기를 AI 초안 생성 완료로 표시하지 않는다.
- 기본 기능 선반영과 headless 브라우저 검증은 위의 사용자 직접 지시로 승인·완료됐다. 사용 중 새 조건이나 범위가 필요하면 해당 선택만 별도로 확인한다.
- 모바일은 타입·로직 검사 범위다. 좁은 웹 화면 검증을 native 모바일 UI 검증으로 확대하지 않는다.
- native 질문이 미해결인 상태에서 제공자 프로세스가 재시작된 경우의 완전한 질문 복구는 이번 수정의 완료 주장에 포함하지 않는다. 전달 불명을 새 실행이나 재전송으로 해결한 것으로 표시하지 않는다.

기본 워크플로는 운영에 반영됐으며, 새 범위의 승인을 기다린다는 이유로 이미 승인된 기본 교체를 보류하지 않는다.
