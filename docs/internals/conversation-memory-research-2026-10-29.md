# 대화 연속성과 기억 검색 조사

## 공용 사용자 지침 전달 수정 (2026-11-01)

일반 대화와 자동 작업에서 프로젝트 문맥을 조립하면 기억 경로의 사용자 지침을 모두 생략해, 다른 프로젝트에 저장된 환경 공용 지침이 빠지는 문제가 있었다. 조립 결과에 실제로 포함된 출처만 중복에서 제외하고, 나머지 활성 사용자 지침은 기억 경로에서 전달한다. 프로젝트·폴더별 일반 기억의 공개 범위는 바꾸지 않는다. `WorkspaceMemory`와 `ProviderCommandReactor` 집중 테스트에서 공용 지침 보존, 다른 프로젝트의 비공개 지침 제외와 중복 방지를 확인했다. 이 검사는 모든 모델의 실제 지침 준수까지 증명하지 않는다.

조사: 2026-10-29. 사용자는 후속 명령에서 이전 턴과 정리된 기억을 함께 읽도록 요청했다. 운영 데이터의 설정을 읽기 전용으로 처음 집계한 시점에는 활성 프로젝트 16개 중 자동 대화 기억이 켜진 프로젝트가 1개, 꺼진 프로젝트가 14개, 미설정 프로젝트가 1개였다.

이후 사용자가 모든 프로젝트에서 RAG를 켜라고 명시했고, 실행 중인 T3의 설정 명령을 통해 자동 대화 기억이 꺼졌거나 미설정인 15개를 켰다. 설정 명령 응답과 읽기 전용 저장 상태에서 활성 프로젝트 16개 모두 대화 RAG와 자동 기억 연결이 켜진 것을 확인했다. 확인 시점의 메시지 색인 진행 위치는 16개 모두 각 프로젝트의 최신 메시지까지 도달했으며 처리 대기 중인 메시지는 1개였다. 이 수치는 모든 검색의 정확도나 모델의 실제 기억 사용을 입증하지 않는다.

## 현재 T3와 변경

기존 자동 기억 경로는 현재 메시지만 검색한다. 예를 들어 앞선 요청에 작업명이 있고 현재 메시지가 “계속해”라면 검색어에 작업명이 없어 관련 기억을 찾지 못할 수 있다. 최근 대화를 별도로 인계하는 코드는 주로 공급자 전환 시에 실행된다.

사용자는 폴더별 RAG 분리와 현재 작업 폴더의 후속 명령 유지를 선택했다. 기존 프로젝트 간 일반 대화 기억은 프로젝트 ID로 구분하고, 명시적 공용 기억만 다른 프로젝트에 노출한다. 후보는 같은 대화에서 인식 가능한 단일 하위 폴더 경로를 찾아 후속 요청의 폴더 전용 지식 검색에 전달한다. 여러 경로가 등장하면 이전 폴더를 유지하고, 되돌린 메시지는 다시 계산한다. 경로가 실제로 존재하고 작업 루트 안에 있는지 확인하지만 자연어의 의도를 완전히 판정하지는 못한다. 확인 시 활성 폴더 전용 지식은 9개였다.

이 후보는 폴더 전용으로 등록된 지식에만 경로를 적용한다. 일반 대화의 색인과 `workspace_memory` 검색은 프로젝트 단위이며, 같은 대화의 최근 발언도 하위 폴더로 나누지 않는다. 따라서 같은 프로젝트의 하위 폴더별 대화 기억까지 완전히 격리했다고 볼 수 없고, 이 부분은 사용자의 전체 폴더별 분리 요구에 남은 작업이다.

공유 지식의 범위를 프로젝트나 폴더로 바꾼 뒤 비동기 색인 갱신 전 검색이 이전 범위를 사용할 수 있는 결함도 격리 테스트로 재현했다. 후보 코드는 기존 색인의 검색·원문 조회 전에 현재 지식 원본의 상태와 범위를 확인한다. 수정 후 `WorkspaceMemory.test.ts` 16건과 수정 파일에 한정한 TypeScript 검사가 격리 환경에서 통과했다. 이 수정은 운영 재시작과 실제 클라이언트 확인 전이다.

사용자는 기존 인계 상한인 최근 30개 발언, 발언당 2,000자, 합계 약 16,000자를 매 요청에도 적용하도록 선택했다. 후보는 자동 대화 기억이 켜진 경우 이 상한으로 최근 발언을 발췌하고 가장 최근 사용자 발언을 검색어에 함께 사용한다. 검색된 과거 근거는 기존 프로젝트·공용 범위와 검색 상한을 따른다. 현재 메시지와 그보다 뒤에 기록된 같은 대화 메시지는 과거 검색 결과에서 제외한다. 사용자 발언과 에이전트 보고를 구분하고, 현재 지시와 최신 정정을 우선한다고 명시한다. 기억 준비가 실패하면 누락 사실을 AI 입력과 활동 기록에 전달한다.

이 접근은 원문을 삭제하거나 모델로 모든 대화를 요약하지 않는다. 최근 발췌와 관련 근거만 전달하므로 오래된 내용이 모두 프롬프트에 포함되는 것은 아니며, 필요한 원문은 기존 `workspace_memory`의 검색과 페이지 조회로 확인한다.

## 재현과 한계

이 변경에서 수정한 부분만 되돌려 재구성한 이전 `WorkspaceMemory.ts`와 후보를 같은 합성 대화 데이터로 비교했다. 격리된 임시 데이터베이스에서 이전 소스는 최근 대화 블록이 없어 검사에 실패했고, 후보는 바로 전 사용자 발언·에이전트 응답과 관련 기억을 포함하면서 현재·이후 메시지는 제외했다. 설정이 꺼진 경우 자동으로 넣지 않는 동작도 확인했다. 실제 사용자 대화의 답변 정확도, 모델의 기억 활용, 장시간 대화의 지연이나 공급자별 동작은 이 검사만으로 검증되지 않았다.

기존 `evaluate-knowledge.ts`도 격리 환경에서 이전 소스와 앞선 실험 후보로 각각 실행했다. 두 실행은 같은 데이터셋 SHA-256 `698eb0f91bde1f74ad9e255437354a776140b364abe19d3867fe8faf4d459519`, 키워드 모드, 임베딩 모델 없음, 새 임시 캐시를 사용했고 각각 120건 중 96건이 통과했으며 범위 위반과 출처 실패는 0건이었다. 24건은 의미 검색 범주의 사례에서 통과하지 못했다. 이후 추가한 폴더 경로 처리까지 포함한 최종 후보로는 이 비교를 다시 실행하지 않았다. 이 평가는 기존 프로젝트 지식 검색 경로를 검사하며, 이번 최근 대화 전달 경로의 정확도를 측정하지 않는다. 실제 답변 생성과 과금 토큰도 측정하지 않았고, 각 1회 측정의 지연 차이를 성능 개선으로 해석하지 않는다.
