# 오케스트라 장시간 실행 중단 수정 — 2026-09-13

일반 대화의 유휴 세션 정리기가 오케스트라의 독립 실행 키를 대화 ID로 조회했다. 이 키에는 대화 행이 없으므로 activeTurnId 보호가 적용되지 않았고, 작업이 진행 중이어도 시작 후 30분이 지나면 세션을 종료했다. 운영 로그에서 17:14 KST에 이러한 종료가 실제 발생한 것을 확인했다. 짧은 텍스트 실사 테스트로는 이 경로를 검증하지 못했다.

종료 시 어댑터의 마지막 이벤트가 전달되지 않으면 실행기가 결과를 계속 기다렸고, 병렬 결과를 전부 모은 뒤 저장하던 처리 때문에 먼저 완료된 작업도 실행 중으로 남았다.

## 수정

- 실행 소유 정보가 있는 오케스트라 세션은 일반 유휴 정리에서 제외한다. 종료와 정리는 해당 실행기가 관리한다. 일반 대화의 유휴 정리는 유지한다.
- ProviderService가 실행 세션을 명시적으로 정지하면 소유 대화와 실행 ID를 포함한 종료 이벤트를 전달한다. 결과 대기와 중지 처리가 끝없이 남지 않게 한다.
- 병렬 결과는 완료된 것부터 직렬화하여 저장한다. 다른 결과나 사용자 중지 상태를 덮어쓰지 않도록 최신 실행 상태를 읽는다.
- 서버 복구 시 완료된 응답은 재사용한다. 중단된 응답의 스트리밍과 상태를 닫고, 보존된 부분 응답 최대 3,000자를 재시도에 전달한다. 기존 산출물을 먼저 확인하고 남은 단계만 복구하도록 안내한다.
