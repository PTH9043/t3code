# 오케스트라 지휘 AI·복수 모델 실사 검증 — 2026-09-13

Codex 및 Claude를 각각 지휘 AI로 선택하고, 같은 계정의 서로 다른 모델을 참가자로 배정하여 실제 제공자 CLI로 실행했다. 두 실행 모두 완료했으며 모델·추론 강도·검증 순서·산출물을 독립 대조했다. Codex 실행은 최초 검증 중단을 수정한 뒤 해당 단계부터 재개했고, Claude의 새 실행은 재계획과 재시도 없이 통과했다. 브라우저 연결이 없어 실제 선택 화면의 클릭 검증은 하지 못했다.

## 적용한 동작

- 웹·데스크톱 대화의 모델 선택기 → **오케스트라** → 계정별 **모델 추가**에서 같은 Codex 또는 Claude 계정의 여러 모델을 참가자로 추가한다. 지휘자를 포함해 2~8명이며 동일 계정·동일 모델 중복은 막는다.
- 상단 **지휘 AI** 선택 또는 참가자 옆 왕관 버튼으로 지휘자를 지정한다. 참가자 ID는 계정·모델과 독립적이므로 모델 변경이 지휘자 연결을 깨뜨리지 않는다. 지휘 참가자를 제거하면 첫 참가자가 맡는다.
- 각 참가자의 추론 강도를 별도로 저장한다. 이전에는 화면의 기본값만 보이고 실제 실행 옵션에는 없을 수 있었다. 이제 제공자 카탈로그의 기본 선택값도 명시적으로 저장·전달한다. 모델 변경 시 새 모델의 기본값을 적용하고, 이전에 잘못 저장된 선택 표시명은 유효한 ID로 보정한다.
- 새 설정은 **바로 실행**, **실패 복구·재계획 1회**, **선택하지 않은 AI 추가 허용 꺼짐**이다. 저장된 기존 설정을 일괄 덮어쓰지 않는다. 토론 방식에서도 화면에 설정한 복구 한도를 서버로 보낸다.
- 추가 AI 허용이 꺼져 있으면 서버는 선택하지 않은 작업자를 후보에 추가하지 않는다. 지휘 프롬프트는 완료 기준에 필요한 최소 작업 그래프를 요구한다.

여기서 과도한 추론 방지는 불필요한 토론·작업 확대·반복 복구를 줄이고 선택한 effort가 실제 제공자에 전달되게 하는 것이다. 모델 내부 사고량의 상한이나 고정 토큰 절감률을 보장한다는 뜻은 아니다.

## 실사에서 찾고 수정한 불필요한 복구

최초 Codex 지휘 실행은 산출물과 검사 3개가 맞아도 보고서 검증에서 멈췄다. 검증자는 “선행 검증이 완료된 뒤 보고서가 실행됐는가”를 확인하려 했지만, 프롬프트에는 서버 소유의 실행 시각·검증 영수증이 없었다. 로컬 파일에서는 그 기록을 찾을 수 없어 불확실로 판정했다.

정보 복구 오류 문구도 `Grok research node`로 고정되어 있었다. 실제 조건은 제공자 Grok가 아니라 작업 종류 `research`를 검사하고 있었다. 잘못된 문구 때문에 선택하지 않은 제공자가 필요한 것으로 오해할 여지가 있었다.

수정은 다음과 같다.

- 작업 프롬프트에 해당 작업의 직접 선행 노드 상태·완료 시각·검증 결과를 서버 상태에서 조합해 제공한다. 검증 노드에는 검증 대상 작업의 선행 기록을 제공한다.
- 알 수 없는 기록은 unknown/unavailable로 남기고 실패를 성공으로 바꾸지 않는다. 산출물 검사는 별도로 수행해야 한다는 지침을 유지한다. 관련 없는 노드의 기록은 넣지 않는다.
- 복구 안내를 특정 제공자가 아닌 연구·구현 등 작업 역할 기준으로 고쳤다. 기존 검증 조건을 완화하거나 강제로 성공 처리하지 않았다.

수정 후 완료한 계산·정책·보고서 작업은 그대로 두고, 보류 질문에 응답하여 실패한 보고서 검증만 재개했다. 해당 단계는 서버 영수증과 실제 파일을 대조하고 검사 3개를 다시 실행해 통과했으며 Astra가 종합까지 완료했다. 기존 완료 작업의 시도 기록이 재개 전후 동일함도 확인했다.

Claude 지휘의 새 실행에서는 Fable이 같은 영수증을 사용하여 별도 복구 없이 완료했다. 실행 시각을 독립 비교한 결과는 다음과 같다. 시각은 UTC다.

## 후속 보완: 한 대화 안의 작업 목록

웹·데스크톱 대화의 개별 오케스트라 출력 박스를 실행별 작업 목록으로 묶었다. 작업 행 안에서 지시·현재 출력·변경 파일·도구 기록·검증 근거를 열고, 같은 작업의 이전 시도와 당시 모델을 확인한다. 작업별 대화방 생성이나 이동은 추가하지 않았다.

- 전체·실행 중·확인 필요·완료 필터, 모두 접기·펼치기를 제공한다. 아직 시작하지 않은 그래프 작업도 표시한다. 상태 변경만으로 작업 순서를 재정렬하지 않는다.
- 완료 작업은 기본적으로 접히지만 직접 펼친 선택은 유지한다. 선택 상태를 가상 목록 바깥에 두어 스크롤로 행이 다시 마운트되어도 보존한다. 필터·접기 조작 시 자동 최신 출력 따라가기를 해제한다.
- 재시도 시작의 실시간 메시지가 그래프 조회보다 먼저 도착해도 실행 중으로 표시한다. 생성자의 실행 완료와 서버의 검증 대기는 구분한다.
- 도구 호출 ID가 다른 작업에서 재사용돼도 기록이 합쳐지지 않도록 작업별로 구분한다. 오래된 원본 메시지가 미로딩이면 결과 요약임을 표시한다.
- 서버 요청·실행 로직과 계약은 변경하지 않았다. 공통 데이터 조합은 `packages/client-runtime`에 두었고 새 목록 UI는 웹·데스크톱에 적용했다. 모바일 화면은 이번 보완 범위에 포함하지 않았다.

최종 집중 검사 5파일 124개 통과. 웹·client-runtime 타입 검사 및 변경 범위 lint 종료 코드 0이다. `task-list-tests.log`, `task-list-typecheck.log`, `task-list-shared-typecheck.log`, `task-list-lint.log`가 증거다.
