## 대화 인계 실험

실제 `prepareCompactHandoff`로 기존/축소 입력을 구성하고 두 CLI가 과거 기록을 이어받는 상황을 재현한다. 마지막 사용자 수정(`document-only`, 재시작 금지), 미완료 외부 검증, 과거 원문의 정확한 Evidence ID를 모두 보존해야 통과한다. 원문 재조회에 쓴 토큰도 제공자 사용량에 포함된다.

Codex는 양쪽 3/3 통과했다. 총 토큰은 435,619 → 434,327로 **0.30% 감소**에 그쳤으며, 캐시 읽기를 제외한 입력은 70,497 → 81,548로 **15.68% 증가**, 총 시간은 117.03 → 158.18초로 **35.16% 증가**했다. 축소 입력은 8,685 → 2,614자로 짧아졌지만 실제 작업에서는 원문 조회도 필요했다. 이 단일 사례로 인계 최적화의 일반적인 절감·속도 개선을 주장할 수 없다.

Claude 축소 방식 3회는 모두 통과했다. 기존 방식 3회는 제공자가 `reasoning_extraction` 오류로 거부했고, 결과 파일은 변경되지 않았다. 실패와 3회 합계 107,502토큰을 보존했다. 비교 기준이 성립하지 않으므로 Claude 인계 절감률은 산출하지 않는다. 이 실패를 회피하려고 모델·권한을 바꾸거나 입력을 다시 써서 재시도하지 않았다.

Claude 축소 방식의 합계는 450,721토큰이었다. 두 제공자의 축소 방식 6회 모두 저장된 원문을 조회한 도구 이벤트와 정확한 결과 파일을 확인했다. 이는 하나의 합성 대화에서 정정·미완료·과거 근거를 보존한 결과이며 전체 실제 대화의 보존율을 뜻하지 않는다.

## 발견하고 수정한 문제

1. **무관한 기억 주입:** 새로운 16질의의 첫 실행에서 관련 모드는 15/16, 기존 모드는 7/16이었다. 결제 문구 번역 요청에 `사용자`라는 단어 하나만 일치해 오케스트라 운영 기억이 들어갔다. 일반적인 사용자 표현만으로는 주제를 일치시키지 않게 수정했다. 필수 사용자 지침과 실제 오케스트라 요청의 기억은 유지한다. 수정 후 16/16이며, 이 후속 점수는 개선에 사용한 개발 평가다. 사람의 기대 근거 검토를 완료했다고 주장하지 않는다.
2. **Windows 인계 원문 저장 실패:** 해시 파일명을 임시 디렉터리 접두사에도 넣어 `FileSystem.makeTempDirectoryScoped`가 `ENAMETOOLONG`으로 실패했다. 기존 동작은 이를 `source-unavailable`로 처리하고 긴 인계를 그대로 전달했다. 원자적 저장의 임시 접두사를 짧게 고쳐, 원문 보존·해시 확인 후 축소 입력을 전달할 수 있게 했다. 실제 긴 경로의 저장·덮어쓰기·임시 파일 정리 회귀 검사와 인계 재현을 통과했다.
3. **비교 실행기의 수신기 누수:** 초기 실행기의 `forkChild` 수신기가 이전 작업 범위를 벗어나 살아남아 다른 작업의 완료 이벤트를 소비했다. 작업 범위에 묶인 `forkScoped`로 고치고 연속 네 작업의 수신기 해제를 테스트했다. 중단된 Codex/Claude 각 1회는 native 결과·파일·프로세스 신원과 함께 `harness-recovery/`에 별도 보존했다. 이 두 회의 canonical 사용량은 누락되어 있으므로 전체 실험 소비가 완전 집계됐다고 주장하지 않는다. 품질 실패를 제외한 사례가 아니라 실행기 장애 복구다.

검색 수정 후 실험의 30종 입력/원문 조합이 기존 Claude 실행과 byte-identical임을 확인했다. 완료된 Codex·Claude 사이에서도 30종 프롬프트·원문·작업 지침 파일이 모두 같았다. 모델 작업 결과에 맞춰 입력을 바꾼 비교가 아니다.

## 재현과 검증

- 실행기: `apps/server/scripts/token-optimization-pilot.ts --provider=codex|claude`; 인계 실험은 `--suite=handoff`.
- 집계: `apps/server/scripts/summarize-token-pilot.mjs`, 인계는 `--suite=handoff`.
- 같은 제공자/실험군의 실행기를 중복 실행하지 않는다. 기존 결과는 건너뛰며, 새 실험은 별도 증거 디렉터리를 사용한다.
- 두 `summary.json`에 전체/작업별 집계와 72회 결과, 모델 설정, 입력·이벤트 해시를 보존했다. `cross-provider-input-audit.json`은 RAG 입력 일치를, 인계의 `original-retrieval-audit.json`은 축소 방식 6회의 원문 조회 도구 이벤트를 기록한다. 문서 산출물과 협업 검증 보고서도 내용으로 확인했다.
- 토큰/인계/선택/원문/형식/투영 집중 51개, Codex·Claude 어댑터와 요청 경로 145개, 검색 회귀 40개, 원자적 저장·인계 15개, 수신기 회귀 1개가 통과했다. 중복 검사 파일이 있으므로 독립 테스트 총수로 합산하지 않는다.
- 서버 타입 검사 exit 0, 변경 범위 lint 오류 0. 전체 저장소 검사는 실행하지 않았다.
- 웹/데스크톱/모바일은 같은 서버 입력 경로와 원자적 파일 저장 변경을 사용한다. UI 코드는 변경하지 않았다. 실제 화면 조작·원격 단말 검증은 별도이며, 브라우저 조작 승인 답변을 받지 않아 실행하지 않았다.

이번 실험에서 Claude RAG는 감소를 관측했지만 Codex RAG는 총량 감소를 입증하지 못했다. 세션 인계는 원문과 상태 보존을 확인했으나 두 제공자 공통의 절감률을 확보하지 못했다. 이 결과에 맞춰 모델·추론 수준이나 운영 설정을 자동 변경하지 않았다.

배포·커밋·운영 프로젝트 설정 변경을 수행한 기록은 아니다. 이 문서는 소스 변경과 실제 CLI 실험 결과를 다룬다.

## 2026-11-11: 긴 기억 발췌 중복 비교

동일 프로젝트·출처의 검색 발췌 전체가 이미 전달된 경우에만 중복 발췌를 생략하며 출처·검증 상태와 원문을 유지한다. 발췌 밖 원문은 별도 확인이 필요하다고 표시한다. 다른 출처 또는 발췌 일부만 일치하면 생략하지 않는다. 출처별로 실제 삽입된 범위를 함께 전달하므로 사용자 요청 등 다른 영역에 같은 문장이 존재하는 것만으로 생략하지 않는다. 주제 없는 “이어서” 후속어는 이전의 실질적 검색 주제로 되돌아간다.

운영 대화에서 선택된 Codex `gpt-6.1-terra`와 `xhigh`를 유지하고, 사용자의 실제 요청 및 해당 프로젝트 저장 자료를 분리해 동일 발췌 6개가 겹치도록 구성한 재현 입력을 T3 Codex 어댑터로 각각 실행했다. 입력은 29,169→26,643, 출력은 130→138, 합계는 29,299→26,781 토큰(8.59% 감소)이다. 두 응답은 요청된 항목과 저장 자료가 주장한 네 수치를 확인했다. 제공자가 보고한 캐시 읽기는 두 실행 모두 0이다. 하나의 대화에서 구성한 분리 재현 시험이며 운영 대화 전체나 실제 일반 작업의 평균 절감률을 뜻하지 않는다.

별도의 동일 고정 데이터셋(120개, SHA-256 `698eb0f91bde1f74ad9e255437354a776140b364abe19d3867fe8faf4d459519`) 검색 시험에서 키워드 96/120, 기존 bge-m3 의미·키워드 결합 120/120이 통과했다. 이는 합성 자료의 검색 근거 판정이며 실제 답변 정답률이 아니다. 의미 검색 설정은 변경하지 않았다.
