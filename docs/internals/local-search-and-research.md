# Local search and research

`ProjectionWorkspaceRag` applies project, folder, attachment and excluded-source constraints before selecting semantic candidates. Ollama embeddings and content hashes form a derived, per-project/model cache under `userdata/semantic-rag`. Keyword results and qualifying semantic results are combined with reciprocal rank fusion. Cold searches enqueue durable background indexing and report partial coverage. External embedding endpoints are rejected. Prompt composition releases its SQL read transaction before embedding I/O.

Ollama requests share one embedding permit. Document batches have a 30-second deadline for CPU inference; query embeddings have a 5-second deadline that includes waiting for that permit. A long background batch cannot hold a query indefinitely: a timed-out query falls back to keyword results without cancelling the document batch or leaking a queued permit. The configured embedding model must already be installed in the server's Ollama instance.

PDF extraction version 2 optionally runs Korean/English Tesseract OCR on pages without usable text. Verified language models are cached under `userdata/document-ocr`; only model files are downloaded. Rendering and recognition stay local. Recognition includes cancellation and a deadline, reports partial extraction, and preserves the source attachment. The canvas dependency must match PDF.js's native canvas version.

`workspaceResearch.status`, `.run`, and `.configureKey` share typed contracts across clients. The authenticated `workspace_research` MCP tool checks the caller thread's project before accessing research. API keys use `ServerSecretStore`. The journal under `userdata/grok-research` contains responses, cost receipts and opaque xAI history, and never the key. Calls are reserved before network transmission; incomplete or uncertain calls cannot be automatically replayed. Completed responses can replay only their idempotent knowledge-save command.

Per-response cost ticks include search and compaction. A per-environment semaphore serializes paid calls and daily budget checks. Unknown costs remain explicit; a configured daily limit blocks additional calls while today's cost is unknown. The limit is checked before a call and cannot bound the cost of an in-flight request. Prompt caching uses a stable prefix/key. Long follow-ups preserve the `/responses/compact` output verbatim, including opaque fields.

Development task receipts carry a failure classification, code fingerprint and chosen recovery strategy. A repeated owner objective requires a recovery strategy. Only a pending, transient delivery permits one identical retry; accepted/uncertain delivery is never treated as a pending network retry. Unchanged code and a repeated failed repair strategy require new evidence or a different strategy. Existing execution fences, native session identity and goal budgets remain authoritative.
