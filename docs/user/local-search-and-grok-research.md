# 로컬 의미 검색과 API 조사

**설정 → 일반 → 검색용 모델**에서 외부 자료 조사에 사용할 모델을 추가하고 순서를 정할 수 있습니다. 일반 대화, 하위 작업 모델, 비서와 오케스트라가 같은 목록을 사용합니다. 현재 답변을 맡는 모델은 대화방이나 비서에서 따로 지정합니다.

외부 검색이 필요하면 목록의 첫 모델부터 시도합니다. 연결에 실패하거나, 결과가 비어 있거나, 출처가 질문에 답하기에 부족하면 다음 모델로 넘어갑니다. 목록을 모두 사용한 뒤에는 현재 AI가 허용된 검색 도구로 직접 확인합니다. 직접 검색으로도 답을 확인하기 어려우면 확인된 내용과 남은 질문, 실패 이유를 보고합니다.

프로젝트 자료 검색은 키워드 검색과 로컬 의미 검색을 함께 사용합니다. 정확한 파일명·식별자와 뜻이 비슷한 표현을 함께 찾고, 질문에 필요한 근거 조각만 AI에게 전달합니다. 검색어와 일치하는 단어가 없는 자료는 의미 유사도가 0.56 이상일 때만 검색 결과나 관련 기억으로 선택할 수 있습니다. 검색 결과에서 방식과 의미 색인의 준비 상태를 확인할 수 있습니다.

설정 → 일반 → AI 검색·문서 인식에서 의미 검색, Ollama 주소, 임베딩 모델을 설정합니다. Ollama는 서버가 실행되는 컴퓨터에서 켜져 있어야 합니다. 기본 모델은 `embeddinggemma:300m-qat-q4_0`이며, 실제로 설치된 임베딩 모델 이름을 입력해야 합니다. 의미 검색 주소는 이 환경의 localhost만 허용합니다. Ollama가 꺼져 있거나 모델을 사용할 수 없으면 키워드 검색과 안내 메시지를 제공합니다. 설정 검색에서도 `RAG`, `OCR`, `Grok`으로 이 항목을 찾을 수 있습니다.

의미 색인은 프로젝트별로 파일 내용과 모델에 맞춰 재사용합니다. 자료가 바뀌면 새 내용으로 계산합니다. 첫 검색은 필요한 색인을 백그라운드에서 준비하도록 요청하고 현재 준비 상태를 표시합니다. 검색 범위에 속한 자료를 조금씩 읽어 의미 검색에 사용하며, 키워드 검색도 함께 사용합니다. 색인을 만드는 동안 검색 요청이 오래 대기하면 키워드 결과를 먼저 제공합니다. 프로젝트·폴더 범위, 보관한 자료, 제외한 첨부와 오래된 자료에 대한 기존 제한을 유지합니다. 원격 웹·휴대폰에서도 검색과 OCR은 연결한 서버에서 처리됩니다.

사용할 의미 색인이 아직 없으면 결과에 **키워드 검색**으로 표시합니다. 모델 미설치, Ollama 연결 실패, 대기 시간 초과, 잘못된 응답은 각각 다른 안내로 구분합니다. 모델이 없으면 서버에 준비할 모델 이름을 표시하며, 원격으로 접속했다면 서버 컴퓨터의 설치 상태를 확인해야 합니다. 색인 작업의 실패 원인은 앱을 다시 시작해도 남고, 이후 색인을 정상 생성하면 사라집니다. 모델 준비와 재시도 중에도 키워드 검색 결과를 사용할 수 있습니다.

폴더나 검색 범위를 바꾸고 돌아오면 최근에 준비한 색인을 재사용합니다. 결과에는 현재 검색 범위의 자료만 포함됩니다. 재사용 색인의 저장량은 제한하며, 오래 사용하지 않은 색인은 필요할 때 다시 계산합니다.

프로젝트 제어 센터의 지식/검색 화면에 **API 최신 정보 조사**가 있습니다. Grok을 선택하면 웹, X 또는 둘 다 조사할 수 있습니다. 공식 도메인은 최대 5개, X 계정은 최대 20개까지 좁힐 수 있습니다. X 날짜는 UTC 기준이며 시작일은 포함하고 종료일은 제외합니다. 완료한 조사를 선택해 후속 질문을 이어갈 수도 있습니다. 모바일은 대화의 토큰 사용량 패널에서 조사와 키 연결, 비용·결과 확인을 지원합니다. 상세 필터와 비용 상한은 웹·데스크톱에서 설정합니다.

**API 최신 정보 조사**에서 Grok 외에 OpenAI, Claude, Gemini 또는 등록된 사용자 지정 API를 선택할 수 있습니다. OpenAI와 Claude는 해당 API에서 웹 검색을 지원하는 모델 ID와 API 키를 입력합니다. X 계정과 날짜 필터는 Grok에서만 적용합니다. 사용자 지정 API는 등록된 계정과 모델을 선택하며, 자체 웹 검색을 선택하면 해당 서버가 웹 검색을 지원하고 출처 URL을 반환해야 합니다. 지원하지 않거나 출처가 없는 응답은 RAG에 저장하지 않습니다.

Gemini는 두 방식이 있습니다. **Google 검색 보고서**는 프로젝트 조사 화면에서 Google 검색 제안과 함께 표시되며 조사 기록이나 프로젝트 RAG에 본문·링크가 자동 저장되지 않습니다. 대화 AI의 도구 응답은 대화 기록에 저장될 수 있으므로 이 보고서는 해당 도구로 호출하지 않습니다. 이는 [Google의 검색 근거 결과 이용 조건](https://ai.google.dev/gemini-api/terms)에 따른 것입니다. **다른 API 조사 분석**은 앞서 완료한 Grok·OpenAI·Claude 등 비Google 검색 결과를 선택해 Gemini에 전달하고 분석 결과를 RAG에 저장합니다. 사용자 지정 API도 기존 조사 자료를 선택해 분석할 수 있습니다. 선택한 자료가 해당 모델 제공자에게 전송됩니다.

조사 API 키는 CLI 로그인과 별도일 수 있습니다. 제공자별 저장 키는 서버의 비밀 저장소에 보관하고 화면에 다시 표시하지 않습니다. 저장 키를 삭제해도 서버 환경이나 계정에 설정된 해당 API 키는 계속 사용될 수 있습니다. 사용자 지정 API는 선택한 등록 계정의 주소·키를 사용합니다. Google 검색의 화면 전용 보고서를 제외한 결과는 출처 URL, 수집 시각, 검증 미완료 표시와 함께 프로젝트 검색 자료에 저장됩니다. 조사 결과의 근거를 확인한 뒤 구현 판단에 사용하세요.

비용 화면은 이 조사 기능에서 제공자가 보고한 실제 USD 금액만 표시합니다. 제공자가 금액을 반환하지 않거나 호출 응답을 확인하지 못했으면 미확인 호출로 표시하며 임의의 가격으로 계산하지 않습니다. Codex·Claude·Grok CLI 구독과 다른 프로그램의 API 비용은 포함되지 않습니다. 캐시 입력 토큰도 응답에 보고된 값만 표시합니다.

하루 조사 금액 상한은 같은 서버의 모든 프로젝트에 적용하며 UTC 날짜를 기준으로 합니다. 누적 보고 비용이 상한에 도달하면 다음 유료 호출을 멈춥니다. 상한을 설정한 상태에서 오늘 미확인 호출이 있으면 다음 호출도 보류합니다. 진행 중인 호출이 완료되면서 상한을 넘을 수 있으므로 결제 금액의 절대 상한은 아닙니다. 빈 값으로 저장하면 상한을 해제합니다. 자동 개발의 프로젝트 토큰 예산은 별도로 유지됩니다.

Grok 조사에서는 동일한 지시와 캐시 키를 재사용합니다. 긴 후속 조사에는 xAI 문맥 압축을 사용하며 압축 호출의 비용도 기록합니다. 제공자가 반환하는 압축 항목은 그대로 다음 xAI 요청에 사용합니다. 기존 코딩 CLI의 대화 기록과 캐시 처리는 해당 제공자가 관리합니다.

연결이 끊기거나 응답이 완결되지 않은 호출은 자동 재전송하지 않습니다. 비용 기록과 오류 안내를 확인하세요. 응답과 비용은 저장됐지만 프로젝트 자료 저장만 실패한 경우에는 같은 요청 ID로 자료 저장을 다시 시도할 수 있습니다. 이때 이미 완료한 API 호출을 반복하지 않습니다.
