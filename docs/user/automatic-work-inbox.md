# 자동 업무 접수함과 업무 양식

프로젝트 운영의 **자동 작업 성과**에서 **자동 업무 접수함**을 사용할 수 있습니다. 업무 양식에 입력 항목·작업 지시·실행 방법·성공 조건을 저장한 뒤 작업을 접수하세요. 같은 프로젝트의 AI 실행이 진행 중이면 기다렸다가 처리합니다.

## 업무 양식 만들기

웹·데스크톱에서 **자료 조사**, **이슈 수정 후보**, **파일 처리**, **AI 없이 명령 실행** 중 하나를 선택하세요. 이름과 입력 항목, 지시문을 편집하고 저장하면 새 버전이 생깁니다. 지시문에서는 `{{topic}}`처럼 입력 이름을 참조할 수 있습니다.

AI 업무에는 저장한 실행 프로필을 선택할 수 있습니다. 프로필의 모델·역할·병렬·worktree 설정과 검증 명령을 함께 보관합니다. 프로필을 나중에 바꿔도 이미 접수한 업무는 원래 버전을 사용합니다. **프로젝트 기본 역할 사용**을 선택하면 프로필 연결을 해제할 수 있습니다.

**새 작업 접수 허용**을 끄면 그 양식으로 새 작업을 접수하지 않습니다. 이미 접수한 작업은 기존 조건대로 진행하므로 필요한 작업을 개별 보류·취소하세요. 양식 편집은 웹·데스크톱, 저장한 양식의 실행·상태 확인·보류·취소는 모바일에서도 지원합니다.

## AI 호출 전에 변화 확인하기

**항상 실행**, **파일 내용이 바뀔 때 실행**, **확인 명령이 변경을 보고할 때 실행** 중 하나를 선택할 수 있습니다.

파일 확인은 프로젝트 안의 지정 파일 내용을 이전에 정상 완료한 실행과 비교합니다. 첫 실행이거나 내용이 바뀌면 진행하며, 같은 내용이면 **변화 없음 · AI 생략**으로 종료합니다. 파일이 없거나 읽기 실패가 나면 실패로 기록합니다.

확인 명령은 읽기 전용으로 작성하세요. 종료 코드 0과 다음 JSON 출력이 필요합니다.

```json
{ "changed": true, "context": "이번 작업에 필요한 변경 자료", "fingerprint": "선택한 출처 버전" }
```

`changed`는 필수이며 `false`이면 본 작업을 생략합니다. `context`는 AI에 전달할 선택 자료입니다. `fingerprint`를 제공하면 서버가 이전 정상 완료 결과와 비교합니다. 실패한 작업의 버전은 다음 정상 완료의 기준으로 앞당기지 않습니다. 잘못된 JSON·출력 초과·시간 초과·0이 아닌 종료 코드는 ‘변화 없음’으로 처리하지 않습니다.

단순 집계·변환처럼 명령만으로 끝낼 수 있는 업무는 **AI 없이 명령 실행**을 선택하세요. 명령은 Windows에서 CMD로 실행되며 PowerShell 명령은 저장할 수 없습니다. 입력은 명령 문자열에 직접 삽입하지 않고 스크립트가 환경 변수 `T3_TASK_INPUTS_JSON`을 JSON으로 읽습니다.

## 완료와 결과 확인

AI의 답변 완료 뒤 서버가 저장한 검증 명령과 필수 산출물을 검사합니다. 산출물은 프로젝트 루트 기준의 상대 경로이며, 실행 전과 내용이 같거나 비어 있으면 통과하지 않습니다. JSON 산출물에는 필수 최상위 필드도 지정할 수 있습니다. worktree에서 만든 변경은 프로젝트 루트에 반영된 뒤 이 검사를 통과할 수 있습니다.

표시되는 **설정한 결과 검사 통과**는 해당 명령·파일 조건이 통과했다는 뜻입니다. 이슈 수정에는 관련 테스트 등 실제 성공 조건을 설정하세요. 문서 파일의 생성 확인과 문서 내용의 정확성은 각각 확인해야 합니다. AI 업무에 명령·산출물 조건이 없으면 **응답 완료 · 검증 필요**로 남습니다. 이 경우 양식을 보완해 새 업무로 접수하세요.

**입력·실행 자료**에서 양식 버전, 현재 시도, 종료 코드, 결과 해시와 저장 출력을 확인할 수 있습니다. 새 시도로 재실행하면 원래 입력·양식을 유지하고 시도 번호를 올립니다. 이전 시도의 상태와 실행 자료도 보존됩니다.

실행·검증 중 서버가 중단되면 **수행 결과 재확인 필요**로 남고 명령을 자동 재생하지 않습니다. AI 실행 기록이 있으면 **기존 실행 재확인**으로 연결할 수 있습니다. **새 시도로 재실행**은 실제 업무를 다시 수행하므로 이미 반영된 변경을 확인한 뒤 사용하세요. 취소 요청 뒤에는 실행이 정리될 때까지 **취소 처리 중**으로 표시합니다.

## 예약에 연결하기

프로젝트 운영의 스케줄러에서 **저장한 업무 양식**을 선택하고 입력·실행 시간을 지정하세요. 등록 당시 양식 버전과 입력을 보관합니다. 매일·주기·한 번·협업 완료 후 예약을 사용할 수 있습니다. 양식의 기본 입력값은 해당 버전에 저장된 값을 사용합니다.

이전 회차의 업무가 진행·보류 중이거나 검증·수행 결과 재확인이 필요하면 새 회차를 건너뛰고 예약에 이유를 표시합니다. 미확인 결과를 확인하고 취소로 대기를 종료하거나, 양식을 보완해 새 예약을 만드세요. 취소가 이미 수행한 변경을 되돌리지는 않습니다. 각 회차의 접수와 결과는 자동 업무 접수함에서 확인하세요. 일반적인 직접 입력 예약의 동작은 [실행 프로필과 완료 후 예약](execution-profiles-and-follow-ups.md)을 참고하세요.

## 외부 이벤트 식별

외부 이벤트에는 출처와 이벤트 ID를 지정할 수 있습니다. 같은 환경·프로젝트·출처·ID·입력은 기존 접수를 반환합니다. 입력이 바뀌면 새로운 이벤트 ID를 사용하세요. 접수 기록은 서버를 재시작해도 유지됩니다.

GitHub 이슈 가져오기와 JSON 접수 도구도 제공합니다. 도구는 인증된 환경 연결로 접수하며, GitHub 가져오기는 이슈를 읽어 업무 입력으로 만듭니다. 사용 방법은 [자동 업무 연결 도구](../operations/automatic-work-intake.md)에 있습니다.
