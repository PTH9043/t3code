# 하위 모델과 하위 API

답변 모델이 일을 나눠 맡길 대상을 정합니다. 대화에서 고른 답변 모델은 바뀌지 않습니다.

설정 → 제공자에서 Claude 또는 Codex 계정을 펼치면 **하위 모델** 구역이 있습니다. 세 가지를 고릅니다.

| 구역                  | 맡기는 대상                                              | 적용 시점           |
| --------------------- | -------------------------------------------------------- | ------------------- |
| 같은 계정의 하위 모델 | 같은 계정의 다른 모델 (Claude 일꾼, Codex 하위 에이전트) | 저장 후 새 세션부터 |
| 역할을 맡길 다른 모델 | 다른 제공자를 포함한 아무 계정의 모델                    | 바로 (다음 턴부터)  |
| 잡일용 하위 API       | 등록해 둔 API 계정의 모델                                | 저장 후             |

"같은 계정의 하위 모델"과 "잡일용 하위 API"는 고른 뒤 **저장**을 눌러야 반영됩니다. 저장하면 그 계정에서 진행 중인 대화가 중단될 수 있습니다. "역할을 맡길 다른 모델"은 고르는 즉시 저장되고 진행 중인 대화를 건드리지 않습니다.

## 전역 모델 설정

웹·데스크톱에서는 대화 상단의 **모델 설정** 또는 **설정 → 일반 → 전역 모델 설정**을 여세요. 모바일에서는 대화나 새 작업의 **전역 하위 모델**, **전역 답변 스타일**을 누르세요. 저장한 값은 같은 서버의 모든 프로젝트와 대화에서 공유합니다.

- **전역 하위 모델**: 연결된 계정에서 모델을 추가하고 역할과 세부 지시를 정한 뒤 **팀 저장**을 누르세요. **전역 팀 비우기**는 T3 위임 목록을 비웁니다. 제공자 자체의 하위 에이전트 설정은 별도입니다.
- **전역 답변 스타일**: 기본·간결·상세·친근·전문 중 하나를 고르고 말투, 길이, 설명 방식, 자유 지시를 저장할 수 있습니다. 다음 요청부터 적용되며, 오케스트라에서는 최종 답변에 적용됩니다. 현재 요청에 지정한 형식과 말투가 우선합니다. **전역 스타일 해제**를 누르면 전역 스타일 없이 답합니다.

대화 하나만 다르게 쓰려면 대화 상단 **모델 설정**의 **하위 모델 → 이 방에서 커스텀 사용**과 **이 방 답변 스타일**을 쓰세요. 모바일에서는 대화 뷰어에 있습니다. 대화에 저장한 팀과 스타일은 전역 설정보다 우선하고, **글로벌 팀 사용**과 **전역 스타일 사용**을 누르면 전역 설정을 다시 따릅니다. 아직 보내지 않은 새 대화에서 정한 값은 첫 요청과 함께 저장됩니다.

이름을 붙여 저장한 설정을 골라 적용하는 목록은 없습니다. 일반 답변 모델은 기존 대화의 모델 선택기에서 계속 바꿀 수 있습니다. 뷰어에는 다음 요청의 팀과 이미 실행된 하위 AI의 작업 기록이 각각 표시됩니다.

## 같은 계정의 하위 모델

### Claude: 지휘자 모드 일꾼

대화에서 고른 모델이 지휘자로 계획과 검토를 맡고, 큰 구현은 여기서 고른 모델로 실행되는 `worker` 하위 에이전트에 맡깁니다. 기본 일꾼을 고르고, **답변 모델별로 다르게**에서 답변 모델마다 다른 일꾼을 고를 수 있습니다. "끄기"는 그 답변 모델에서 지휘자 모드를 쓰지 않습니다.

### Codex: 하위 에이전트 모델

Codex가 일을 나눠 맡기는 하위 에이전트의 모델입니다. 기본값은 "답변 모델과 같음"이고, 답변 모델마다 다른 하위 모델을 고를 수 있습니다.

- 역할을 고정한 에이전트는 그대로입니다. `~/.codex/agents`나 프로젝트 `.codex/agents`의 에이전트 정의 파일에 `model`을 적어 둔 에이전트는 이 설정과 관계없이 그 모델로 실행됩니다.
- 대화 도중 답변 모델을 바꾸면 그 턴부터 새 답변 모델에 지정한 하위 모델을 쓰도록 Codex에 알립니다. 세션을 새로 시작하면 설정이 Codex에 직접 적용됩니다.
- 하위 에이전트를 쓸지, 몇 개를 쓸지는 Codex가 판단합니다. 하위 에이전트 사용량은 그 요청의 사용량에 더해지고, 답변 모델 이름으로 기록됩니다.
- Codex CLI 0.169.0에서 확인했습니다. 이 설정을 모르는 이전 버전에서는 적용되지 않습니다.

## 역할을 맡길 다른 모델

답변 모델 아래에 다른 모델을 역할과 함께 둡니다. 다른 제공자의 모델도 됩니다. 예를 들어 Claude Opus가 답변할 때 Codex 모델 셋을 조언자·일꾼·탐색으로 둘 수 있습니다.

한 줄에 답변 모델(전체 또는 특정 모델), 하위 모델(계정 · 모델), 역할을 고릅니다.

| 역할          | 하는 일                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------- |
| 일꾼          | 지시받은 구현과 수정을 하고, 확인한 뒤 바뀐 것과 남은 것을 보고합니다.                    |
| 조언자·비판자 | 파일을 고치지 않습니다. 계획과 결과를 비판적으로 검토해 오류·위험·빠진 확인을 짚습니다.   |
| 탐색·보고     | 파일을 고치지 않습니다. 파일·명령·문서를 빠르게 찾아보고 정리해 전달합니다.               |
| 설계          | 작업 순서, 의존 관계, 완료 기준을 제안합니다.                                             |
| 검증          | 범위가 정해진 검사를 실행하고, 통과·실패·미실행 항목을 근거와 함께 보고합니다.            |
| 문서화        | 지정된 문서를 작성하거나 수정합니다.                                                      |
| 오류 진단     | 로그와 코드에서 확인한 증상을 정리하고, 근거 있는 원인과 검증하지 않은 가설을 구분합니다. |
| 데이터 분석   | 분석 방법과 단위, 누락 데이터, 해석의 한계를 함께 정리합니다.                             |
| 번역·현지화   | 원문의 의미, 이름, 수치, 서식을 지켜 번역 결과를 답변으로 전달합니다.                     |

전역 팀과 대화의 팀을 편집하는 화면에서는 일꾼·조언자·탐색이 작업·검토·조사로 표시됩니다. 나머지 역할 이름은 같습니다. 역할을 바꾸면 하위 모델이 받는 지시문이 그 역할의 것으로 바뀌고, 세부 지시는 그 뒤에 붙습니다.

- 답변 모델은 `workspace_delegate` 도구로 일을 맡기고, 결과를 확인한 뒤 씁니다. 맡길지 말지는 답변 모델이 판단합니다.
- 하위 모델은 같은 작업 폴더에서 실제 에이전트로 실행됩니다. 대화 내용은 보지 못하고, 답변 모델이 적어 준 지시만 받습니다.
- 하위 모델의 진행 상황과 답은 같은 대화에 별도 블록으로 보이고, 사용량은 하위 모델 이름으로 따로 집계됩니다.
- 하위 모델의 권한은 그 대화의 권한을 따릅니다. 승인이 필요한 권한에서는 하위 모델의 승인 요청도 같은 대화에 뜹니다. 계획 모드에서는 일꾼에게 맡길 수 없습니다.
- 한 대화에서 동시에 6개까지 실행합니다. 위임 상태는 대화 단위로 보존되어 질문 카드나 자동 복구로 턴이 바뀌어도 다음 턴에서 결과를 수령할 수 있으며, 사용자가 중지를 누르거나 명시적으로 취소할 때만 멈춥니다.
- 오래 걸리는 일은 140초마다 `delegationId`와 함께 "실행 중" 상태로 돌아오며, 멈춤(5분 이상 무활동) 시 마지막 활동 요약과 함께 경고를 표시합니다. 완료되면 대화에 결과 알림을 기록합니다.
- 하위 모델은 다시 다른 모델에게 일을 넘길 수 없습니다.
- T3 위임 도구를 사용할 수 있는 답변 모델은 매 요청에 그 대화의 팀을 받습니다. 대화에 커스텀 팀이 없으면 전역 팀입니다. 진행 중에 팀을 편집하면 다음 요청에서 적용됩니다.
- 계정이 삭제됐거나 꺼져 있으면 그 줄은 "사용 불가"로 표시되고 쓰이지 않습니다.

## 잡일용 하위 API

리서치 정리, 요약, 번역, 초안 같은 잡일을 값싼 API 모델에 맡겨 답변 모델의 토큰을 아낍니다. 답변 모델은 `workspace_helper` 도구로 일을 보내고 결과를 받아 확인한 뒤 씁니다.

### 준비

1. 하위로 쓸 API를 앱의 사용자 지정 API 계정(OpenCode API 연결)으로 등록합니다. 바이두 千帆(Qianfan) 검색 모델은 **설정 → 일반**에서 확인하고 순서를 정할 수 있습니다. Qianfan 계정이 아직 없다면 검색 모델 영역에서 연결하거나, 설정의 계정 추가 창에서 ‘바이두 Qianfan API 계정 연결’을 눌러 계정 이름, 모델 이름, API 키를 넣으면 등록됩니다. 주소는 `https://qianfan.baidubce.com/v2`, 방식은 chat-completions로 고정되며, 저장할 때 연결을 시험하지 않습니다.
   바이두 계정은 Qianfan 콘솔에서 로그인하고 ModelBuilder용 API 키를 발급해 연결하세요. 검색 모델 순서는 계정 등록 후 일반 설정에서 저장합니다. [바이두 공식 API 인증 안내](https://cloud.baidu.com/doc/qianfan-api/s/vmwbl43ut)
2. Claude 또는 Codex 계정의 **하위 모델 → 잡일용 하위 API**에서 아래 항목을 고르고 저장합니다.

| 설정                    | 내용                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------- |
| API 계정·모델           | 1번에서 등록한 계정의 모델. "사용 안 함"이면 쓰지 않습니다.                                        |
| 하위 API를 쓸 답변 모델 | 모든 답변 모델, 또는 고른 답변 모델만.                                                             |
| 보낼 수 있는 내용       | 기본은 공개 정보·일반 잡일만. 프로젝트 내용도 허용으로 바꾸면 코드와 파일 내용도 보낼 수 있습니다. |

### 알아 둘 점

- 보낸 내용은 하위 API 제공사의 서버로 나갑니다.
- "공개 정보·일반 잡일만"은 답변 모델에 내리는 지시입니다. 앱이 보내는 글의 내용을 검사해 막지는 않습니다.
- 하위 API는 답변 모델이 보낸 글만 봅니다. 파일을 읽거나 명령을 실행하거나 웹을 검색하지 못합니다. 최신 웹 조사는 `workspace_research`를 씁니다.
- 하위 API가 지정되지 않았거나 그 답변 모델에 허용되지 않았으면 답변 모델이 직접 처리합니다.
- 하위 API가 쓴 토큰은 도구 결과에만 표시되고 토큰 사용량 화면에는 더해지지 않습니다.
- Claude의 일꾼(worker) 하위 에이전트와 Codex의 하위 에이전트도 같은 도구를 쓸 수 있습니다.
