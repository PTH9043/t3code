# 한 대화에서 지속 작업실 사용하기

기존 프로젝트 대화의 입력창에서 **모델 선택기**를 여세요. Codex·Claude를 선택하는 같은 메뉴 위쪽에서 **단일 AI / 오케스트라 / 지속 작업실**을 고를 수 있습니다. **지속 작업실**을 선택하고 **사용 시작**을 누르면 그 대화가 Main이 됩니다. 새 임시 대화라면 먼저 메시지를 한 번 보내 대화를 만든 뒤 선택하세요.

Main은 전체 작업을 조율하고, 담당 AI는 각 작업실의 대화와 작업을 이어갑니다. 평소처럼 개발 요청을 입력창에 보내면 Main이 담당 작업실에 일을 배정합니다. 후속 요청도 같은 담당 세션으로 이어지며, 전체 기록은 이 대화에 남습니다. 오케스트라는 요청별 토론·실행에, 지속 작업실은 같은 담당자와 이어가는 개발에 사용합니다.

Architect의 완료된 검토는 결과와 실행 정보가 함께 저장됩니다. Main과 담당자는 상태 조회로 마지막 검토를 다시 확인할 수 있으며, 같은 요청을 다시 확인해도 검토를 중복 실행하지 않습니다. 담당자의 상태 조회는 Main이 결과를 확인한 것으로 처리하지 않습니다. 작업실 생성·배정·검증·통합은 Main이 조율합니다.

설정 화면에서 **Main 모델**과 **담당 AI 모델**을 각각 고르세요. Codex·Claude Code·연결된 OpenCode API 모델을 사용할 수 있고, **담당 AI 추가**로 여러 모델을 함께 등록할 수 있습니다. 오케스트라 참가자 목록과 별도로 저장됩니다.

**통합 전 검증 명령**은 실제 프로젝트에서 쓰는 명령을 한 줄에 하나씩 입력합니다. 예를 들어 `vp test run src/example.test.ts`처럼 적고, 공백이 있는 경로는 따옴표로 감쌉니다. JSON을 작성할 필요는 없습니다. 명령을 비워 두면 대화와 작업 배정은 가능하지만, 자동 목표 진행과 결과 통합 전에 검증 명령을 저장해야 합니다. 사용 중에도 같은 메뉴의 **설정 저장**으로 검증 명령을 수정할 수 있습니다.

입력창 위에는 사용 중인 작업실의 **보낼 대상**과 진행 상태가 표시됩니다. 설정 메뉴에서 **지속 작업실 끄기**를 누르거나 **단일 AI / 오케스트라**로 전환하면 자동 후속 진행이 멈춥니다. 기존 대화·작업·개발 목표는 보존되며, 진행 중이던 자동 개발 목표는 일시정지됩니다. 다시 사용할 때 **목표 재개**로 이어갈 수 있습니다.

DeepSeek를 사용하려면 **설정 → CLI 계정 → DeepSeek 연결**을 누르세요. 계정 추가 화면에서도 **DeepSeek API 계정 연결**을 선택할 수 있습니다. 연결 창의 **DeepSeek 로그인 / API 키 발급**에서 API 플랫폼 계정에 로그인해 키를 발급하고 붙여 넣은 뒤 **확인하고 연결**을 누르세요. 서버가 실제 사용 가능한 모델 목록을 확인한 뒤 계정을 저장합니다. 잘못된 키나 연결 오류가 있으면 계정을 저장하지 않고 원인을 표시합니다.

다른 API는 **OpenCode → API 모델 연결**에서 API 주소, 실제 모델 ID와 키를 저장하세요. Chat Completions 또는 Responses 호환 형식을 선택합니다. 입력 컨텍스트·출력 한도는 사용하는 모델 사양 이하로 설정하세요. 서로 다른 API는 계정을 따로 추가하면 모델 선택 목록에서 구분할 수 있습니다.

저장 후 연결된 모델을 일반 대화, Main, 담당 작업실의 모델로 선택할 수 있습니다. API 키는 서버의 계정별 민감 환경 변수로 보관하고, 다른 화면에 저장된 키를 보내지 않습니다. 키를 비워 두고 주소·모델만 다시 저장하면 기존 키는 유지됩니다. API 연결을 해제해도 일반 OpenCode 설정과 기존 세션 이력은 보존합니다. 기존 외부 OpenCode 서버 URL을 쓰는 계정은 해당 서버의 API 설정을 사용하세요.

질문의 옵션을 클릭하거나 숫자 키로 선택해도 다음 질문으로 자동 이동하지 않습니다. 첫 번째·두 번째·이후 질문 모두 선택을 바꾼 뒤 **다음 질문/답변 제출**로 확정합니다. 복수 선택도 제출 전까지 추가하거나 해제할 수 있습니다.

작업실이 준비되면 같은 입력창의 **보낼 대상**에서 Main이나 담당 작업실을 선택할 수 있습니다. Main의 배정, 담당자의 응답과 실행 내역은 이 대화에 함께 표시됩니다. 작업실 목록을 펼쳐 보는 것만으로 제어권은 바뀌지 않습니다.

담당자에게 직접 보낼 때는 다음 중 하나를 고릅니다.

- **보충 / 후속** 또는 **대기열 추가**: 현재 실행이 끝난 뒤 같은 담당 세션에 전달합니다.
- **중단 후 교체**: 현재 실행을 중단하고 새 지시로 이어갑니다.
- **직접 인수**: Main의 상충하는 배정과 통합을 보류하고 사용자가 계속 조정합니다. 끝나면 **Main에 반환**을 누르세요.

확정된 요구를 바꿀 때만 **확정 요구 변경**을 체크하세요. 예를 들어 “아이템 중첩 한도를 99에서 30으로 바꿔”는 요구 개정을 올리고 이전 상충 지시를 무효화합니다. 질문이나 아이디어를 자동으로 확정 요구로 취급하지 않습니다.

Main은 변경된 요구와 결과를 확인한 뒤 작업을 다시 배정하거나 검증된 커밋을 통합합니다. 통합 검증이 통과한 결과는 로컬 릴리즈 후보입니다. 자동으로 외부에 공개하거나 배포하지 않습니다.

**목표를 정하고 자동 개발**에서 이루고 싶은 목표와 완료조건을 적고 **목표 시작**을 누르세요. Main이 필요한 작업을 정해 기존 담당자에게 배정하고, 결과가 도착하면 추가 지시 없이 검증·로컬 통합을 이어갑니다. 외부 dots 설치나 연결은 필요 없습니다. 진행 상태와 담당자 응답은 같은 대화에서 확인합니다.

**목표 일시정지**는 추가 자동 진행을 멈추며 이미 실행 중인 작업은 마무리됩니다. **목표 재개**로 이어갈 수 있고 **목표 종료**는 대기 중인 목표 작업을 취소하면서 코드와 이력을 보존합니다. 작업실을 직접 인수하면 그 영역의 자동 배정·통합은 반환 전까지 보류됩니다.

자동 Main 진행 횟수와 활성 시간 상한을 설정할 수 있습니다. 이 상한은 토큰 요금 한도가 아니며 현재 실행을 즉시 중단하는 제한도 아닙니다. 확인이 필요한 결정, 불명확한 실행 결과, 진행 없는 반복이 발생하면 자동으로 멈추고 이유를 표시합니다. 앱과 서버가 실행 중이어야 계속 진행합니다. 모바일에서는 대화 결과를 볼 수 있으며 목표 제어는 현재 웹·데스크톱에서 지원합니다.

서버 재시작이나 연결 중단으로 지시가 전달됐는지 불명확하면 같은 작업을 자동으로 다시 배정하지 않습니다. 코드나 요구사항이 바뀌어도 이전 지시의 수락·진행 기록을 먼저 대조합니다. 이미 수락된 지시는 재시도 가능하다는 과거 표시만으로 재전송하지 않습니다. 미수락 통신 실패의 한 번 재시도는 같은 코드·요구 범위에서 관리하며 이전 코드의 실패 횟수와 구분합니다.

진행 기록을 확인한 뒤 직접 새 지시로 바꾸려면 **중단 후 교체**를 사용하세요. 명시적으로 교체한 이전 지시는 대체된 상태로 보존하며 새 지시와 구분합니다.

현재 직접 지시는 텍스트를 지원합니다. 별도 Codex/Claude/OpenCode CLI를 동시에 재개해서 쓰는 방식은 안전하게 조정되지 않으므로 이 입력창을 사용하세요. 작업실 분할·조직 통합·폐기, Cursor·Grok 담당자, 모바일의 API 연결 설정·직접 담당자 선택은 아직 지원하지 않습니다. 기존 일반 대화와 오케스트라 사용 방식은 계속 사용할 수 있습니다.
