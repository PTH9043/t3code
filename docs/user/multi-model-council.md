# 다자간 위원회 · 코드 근거 원장 · PinnedSpec 원클릭 실행

T3 Code는 현재 채팅방의 주력 모델(의장)과 사용자가 전역 설정에 등록한 가변 하위 팀(`1..N`개)을 자동으로 합석시켜, **블라인드 격리 탐색 → 동적 익명 비평 → 코드 근거 원장 검증 → 불변 실행 명세(`PinnedSpec`) 원클릭 위임**까지 하나의 흐름으로 진행할 수 있습니다.

## 주요 기능

1. **가변 하위 팀 자동 합석 (`1+N`석)**
   - 특정 모델에 고정되지 않습니다. 설정에서 하위 모델을 1개만 켜두거나, 5개 이상 배치하거나, 실행 도중 모델을 교체해도 다음 위원회 소집 시 즉시 반영됩니다.
   - 활성 하위 모델이 1개 이상이면 항상 **의무 반론자(`CONTRARIAN_RED`)**가 우선 배정되어 다수파 설계의 회귀·보안·경쟁 조건 위험을 반증합니다.
   - 동일 모델을 여러 슬롯에 배치한 경우에도 디렉터리 샤드 분리와 직교 역할 배정(및 지원 모델 온도 분산)으로 집단사고를 방지합니다.
   - 특정 슬롯의 계정이 오프라인이거나 쿼터가 소진된 경우 건강한 폴백 모델로 자동 치환됩니다.

2. **아첨·동조(Flip) 차단 및 익명 비평**
   - **Round 1 (블라인드 격리)**: 의장과 모든 하위 모델은 서로의 초안을 보지 못한 상태로 각자 로컬 코드를 탐색해 제안을 작성합니다.
   - **Round 2 (동적 익명 비평)**: 실제 모델·계정 이름이 제거되고 `Proposal-1..M`으로 익명화된 구조화 주장과 검증된 근거 포인터만 교환합니다.
   - 새로운 디스크 검증 근거 없이 다수 의견에 동조해 입장을 바꾸면 시스템이 `FLIP_BLOCKED`로 자동 기각하고 원래 입장을 보존합니다.

3. **코드 근거 원장 (`EvidenceLedger`)**
   - 모든 주장의 파일 경로·라인 범위·심볼명은 서버가 디스크 원문 SHA-256과 로컬 코드 그래프 심볼 인덱스로 직접 검증합니다.
   - 존재하지 않는 파일이나 잘못된 심볼을 인용한 환각 근거는 자동 격리되며 합의 가중치 `0`으로 강등됩니다.
   - 채팅방의 **근거 원장 보기** 버튼으로 원장 검증 결과, 익명 해제 대조표, Flip 차단 이력을 확인할 수 있습니다.

4. **원클릭 실행 위임 (`PinnedSpec`)**
   - 미해결 P0 의무 반론이 `0건`이고 검증된 근거가 확보되면 불변 `PinnedSpec` 카드가 생성됩니다.
   - 원장 기여도와 코딩 역량을 기준으로 **추천 1순위 워커**가 자동 선택되며, 실행 직전 드롭다운에서 다른 활성 모델로 즉시 변경할 수 있습니다.
   - 실행 직전 잠금된 모든 대상 파일의 SHA-256 해시를 재대조하므로, 외부에서 파일이 변경된 경우 자동으로 차단하고 **디스크 해시 재검증**을 안내합니다.
   - 기본적으로 Git Worktree에 격리 실행되며, 인수 검증 명령과 독립 검증자 판정을 모두 통과해야 최종 완료 처리됩니다.

## 사용 방법

1. **전역 하위 팀 구성**: 채팅방 상단 `모델 설정` → `글로벌 하위 작업 모델`에서 하위 모델을 등록합니다. 각 슬롯의 `다자간 위원회 옵션`에서 자동 합석 활성 여부, 역량 태그, 고정 역할을 선택적으로 지정할 수 있습니다.
2. **위원회 소집**: 채팅방 상단 `동적 위원회` 바에서 **하위 팀 합석 회의**를 누르고 참여할 슬롯과 안건을 입력해 소집합니다. 기존 `회의 모드` 패널에서도 **전역 하위 팀 합석** 버튼으로 좌석을 한 번에 불러올 수 있습니다.
3. **실행 위임**: 합의가 완료되어 `PinnedSpec` 카드가 표시되면 실행 워커와 Worktree 격리 옵션을 확인한 뒤 **PinnedSpec 원클릭 실행 위임**을 클릭합니다.
