# 확인함과 작업자 메시지

작업실 첫 화면과 프로젝트의 **확인함**에서 질문, 권한 승인, 실행 계획, 오류, 완료 검증과 사용량 제한 대기를 확인할 수 있습니다. 항목을 열어 해당 대화나 실행의 최신 요청에 답하세요. 질문하기, 조건 확인, 실행 전 계획 확인은 각각 선택한 설정을 따릅니다.

오케스트라 실행의 **작업자 메시지 · 실제 인계 입력**을 펼치면 작업 단계에 메시지를 보낼 수 있습니다. 대기 메시지는 다음 작업 입력에 포함됩니다. 이미 실행 중인 작업자는 메시지함 도구로 확인할 수 있으며, 즉시 확인한다고 보장하지 않습니다.

- **다음 입력 대기**: 아직 입력에 넣지 않은 메시지입니다. 취소할 수 있습니다.
- **전송 중**: 보존된 작업 입력에 넣었으며 수락 응답을 기다립니다.
- **제공자 입력 수락**: CLI가 입력을 수락했습니다. 내용 반영이나 검증 완료를 뜻하지 않습니다.
- **작업자 도구 확인**: 수신 작업자가 메시지함 도구로 확인을 기록했습니다.
- **수락 여부 확인 필요**: 중단으로 전달 여부가 불명확합니다. 자동 재전송하지 않습니다. 내용을 확인한 뒤 취소하거나 중복 가능성을 확인하고 재전송을 선택하세요.

같은 전송 ID의 재요청은 중복 저장하지 않습니다. 메시지는 실행별 최대 256개를 보관하며 한도에 도달하면 새 전송을 거부합니다. 화면은 최근 80개 기록과 전체 개수를 표시합니다. 기존 기록을 지우지 않습니다.

**실제 입력 원문**은 업그레이드 이후 앱이 제공자 CLI로 보낸 작업 입력을 보존한 것입니다. SHA-256을 검증한 원문을 읽고 전체 복사할 수 있으며 웹·데스크톱에서는 TXT로 다운로드할 수 있습니다. CLI가 별도로 붙인 시스템 지시나 내부 처리 내용은 포함되지 않습니다. 과거 실행의 입력을 나중에 추측해 만들지 않습니다. 작업 응답 종료 기록과 실제 완료 검증 결과도 구분합니다.

회의 설정의 **사용량 제한 후 자동 재개**는 기본적으로 꺼져 있습니다. 켜면 실제 제한 오류와 사용량 리셋 시각 또는 Retry-After가 확인된 경우 대기한 뒤 재개합니다. 시각을 알 수 없거나 인증·일반 오류이면 기존 오류 처리로 진행합니다. 최대 3회, 단계당 최대 10회와 전체 작업 AI 실행 한도를 함께 지킵니다. 같은 리셋 정보로 계속 재시도하지 않습니다. 대기 예약은 서버 재시작 후 복구되며 취소된 실행은 재개하지 않습니다.

## 모니터 비서 모델

설정의 **모니터 비서**에서 비서가 사용할 AI 연결과 모델을 선택합니다. 비서 창에서 연결한 대화의 기록과 권한을 사용하지만, 비서 모델과 일반 대화에서 선택한 모델은 각각 유지됩니다. 비서 모델은 설정에서 변경하며 진행 중인 요청에는 영향을 주지 않습니다. 선택한 연결이나 모델을 사용할 수 없을 때는 다른 모델로 대신 보내지 않고 설정 확인을 안내합니다.

## 글로벌 하위 팀과 대화별 커스텀 팀

**설정 → 일반 → 전역 모델 설정**에서 모든 대화에 쓸 답변 스타일과 하위 작업 모델을 정합니다. 대화 상단의 **모델 설정**을 눌러도 같은 항목이 열립니다. 모바일에서는 대화 화면이나 새 작업 화면의 **전역 하위 모델**과 **전역 답변 스타일**을 누르세요.

- **글로벌 하위 작업 모델**: 연결한 계정의 모델을 추가하고 역할과 세부 지시를 정한 뒤 **팀 저장**을 누르세요. **제공자**에서 Codex나 Claude를 고르면 해당 계정에 연결된 모델만 표시됩니다. **전체**를 고르면 모든 계정을 다시 볼 수 있습니다.
- **전역 답변 스타일**: 기본·간결·상세·친근·전문 중 하나를 고르고 말투, 답변 길이, 설명 방식, 자유 지시를 적어 저장합니다. 입력 칸은 접혀 있지 않고 바로 보입니다. **전역 스타일 해제**를 누르면 전역 스타일 없이 답합니다.

역할은 작업·조사·검토와 함께 설계·검증·문서화·오류 진단·데이터 분석·번역·현지화 중에서 고릅니다. 역할마다 하위 모델이 받는 지시가 다릅니다. 설계는 파일을 고치지 않고 작업 순서와 의존 관계, 완료 기준을 제안합니다. 검증은 범위가 정해진 검사를 실행해 통과·실패·미실행 항목을 근거와 함께 보고합니다. 문서화는 맡은 문서만 작성하거나 수정합니다. 계획 모드에서는 파일을 고치는 작업 역할과 문서화 역할에 일을 맡길 수 없습니다. [역할별 설명](./helper-models.md)

저장한 전역 설정은 새 대화와 기존 대화의 다음 요청부터 사용됩니다. 진행 중인 요청은 시작할 때 받은 배정으로 마칩니다.

한 대화에서만 다른 팀을 쓰려면 대화 상단의 **모델 설정 → 하위 모델 → 이 방에서 커스텀 사용**을 선택하세요. 주 모델을 바꿔도 그 방의 커스텀 팀이 유지됩니다. **글로벌 팀 사용**을 누르면 이후 글로벌 팀 변경도 다시 따라갑니다. 답변 스타일도 같은 화면의 **이 방 답변 스타일**을 펼쳐 저장하면 그 대화만 전역 답변 스타일 대신 그 스타일로 답합니다. **전역 스타일 사용**을 누르면 전역 답변 스타일을 다시 따릅니다. 모바일에서는 대화 뷰어에서 그 대화의 팀과 답변 스타일을 바꿉니다. 비서의 이름과 역할은 일반 설정에서 하위 팀과 따로 지정할 수 있습니다.

이름을 붙여 저장한 설정을 골라 적용하는 목록은 없습니다. 모델 설정에는 전역 설정과 그 대화의 설정만 있습니다.

## 대화 뷰어

대화방에서 **대화 뷰어**를 열면 현재 요청의 활동과 하위 AI의 작업을 함께 볼 수 있습니다. 대화방 상단의 **하위 모델** 목록에서 작업자를 지정하고 역할과 세부 지시를 편집할 수 있습니다. [대화방 팀 설정 안내](./helper-models.md)

저장된 대화는 상단의 대화 제목을 누르거나 사이드바에서 대화 이름을 우클릭한 뒤 **대화 뷰어 열기**를 선택해도 됩니다.

작업 기록에서는 호출 한 건의 시작부터 종료까지를 한 줄로 봅니다. 줄을 누르면 작업 대상과 상태, 확인된 변경을 볼 수 있습니다. 예를 들어 문서를 읽은 작업은 문서 확인으로 표시합니다. 실제 변경 근거가 있는 작업에서는 변경 파일을 확인할 수 있습니다. 제공자가 실행 모델을 알려 주지 않으면 이번 요청에 배정한 모델임을 표시합니다.

펼친 작업의 한국어 설명에는 이 PC의 무료 모델을 사용합니다. 일반 조사와 상태 설명에는 Granite 8B, 코드 변경·차이·오류에는 Qwen Coder 14B를 우선 사용하며 두 모델에 모두 맞는 작업은 나눠 맡깁니다. 설명에는 작업 종류, 상태, 확인된 변경 수처럼 정리된 정보만 사용합니다. 로컬 모델 사용이 어려울 때도 작업 기록과 확인된 결과는 바로 읽을 수 있습니다.

## 텔레그램 채널을 프로젝트 문서로 읽기

설정의 연결 화면에서 **Telegram 채널**을 열고 문서를 보관할 프로젝트와 채널을 지정하세요. 처음 연결하면 계정에서 읽을 수 있는 과거 글 전체를 수집합니다. 이후에는 4시간마다 마지막으로 읽은 글 다음부터 새 글을 모두 확인합니다. T3가 꺼져 있던 동안의 글도 다음 시작 때 이어서 읽습니다. 채널별로 일시 중지하거나 지금 동기화할 수 있습니다.

문서는 등록한 프로젝트에서 글의 출처와 함께 검색할 수 있습니다. 요약에는 무료 로컬 모델을 먼저 사용합니다. 채널 설정에서 T3에 등록된 CLI 계정과 모델을 직접 선택하고 외부 전송을 허용하면 로컬 요약 실패 시 해당 모델로 이어갑니다. 지정하기 전에는 로컬에서 재시도합니다.

## AutoUsage 업그레이드 방

**프로젝트별 대화 필터** 목록 맨 위에서 **AutoUsage 업그레이드 방**을 누르면 AutoUsage 프로젝트의 일반 대화가 열립니다. 일반 요청의 답변과 도구 기록은 다른 대화와 같은 방식으로 표시됩니다. 이 방은 운영 T3의 계정, 모델, 프로젝트 기억을 그대로 사용합니다. 실행 중에 보낸 새 요청은 대기열에 들어갑니다.

요청을 처리하는 동안에는 대화 위쪽에 작업 상황이 한 줄로 표시됩니다. 마지막으로 기록된 작업의 시각과 종류, 대상 파일 이름, 이번 요청에서 끝난 도구 횟수가 나옵니다. 모델이 작업 계획을 적어 두었다면 몇 단계 중 몇 단계를 끝냈고 지금 어느 단계인지도 함께 보입니다. 2분 넘게 새 기록이 없으면 **N분간 새 작업 기록 없음**으로 바뀌므로, 실행 중 표시만 떠 있고 실제로는 멈춘 경우를 구분할 수 있습니다. 작업 계획은 모델이 직접 남긴 경우에만 나오며, 한 단계가 오래 이어져도 계속 표시됩니다. OpenCode 모델이 적은 할 일 목록도 다른 모델의 계획과 같은 방식으로 대화에 표시됩니다.

작업 기록은 도구를 한 번 쓸 때마다 한 줄로 표시되고, 읽거나 고친 파일 이름이 함께 나옵니다. 작업을 처리하던 프로세스가 결과를 남기지 못하고 종료되면 방은 계속 실행 중으로 남지 않고 **작업 프로세스가 결과를 남기지 않고 종료됐습니다**라는 기록과 함께 멈춥니다. 중단된 요청은 자동으로 다시 실행되지 않으며, 다음 요청은 바로 보낼 수 있습니다.

이 방에서 지원되는 모델의 작업은 T3를 닫아도 계속됩니다. T3가 돌아오면 같은 대화에서 결과를 확인할 수 있습니다. T3가 꺼져 있는 동안에는 프로젝트 기억 조회와 지원되는 하위 모델 위임을 사용할 수 있습니다. **설정 → 일반 → 업그레이드 방**에서 꺼져 있던 동안의 작업 요약을 끄거나, 모델이 질문했을 때 스스로 판단할지 T3가 켜질 때까지 기다릴지 지정할 수 있습니다.
