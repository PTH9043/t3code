# Gemini

이 문서는 T3 Code에서 Google 계정으로 Gemini CLI를 사용하고, 개인용·업무용 계정을 서로
분리하는 방법을 설명합니다. 처음 설치하는 경우에는 [T3 Code 설치](./install.md)를 참고하세요.

여기서 **Google 로그인**은 Gemini Code Assist를 사용하기 위한 인증입니다. Gmail, Google Drive,
Google Calendar 같은 Google Workspace 데이터를 에이전트 도구로 연결하지는 않습니다.
로그인 페이지에는 Gemini CLI가 요청하는 Google 계정 정보와 Google Cloud 권한이 표시될 수 있지만,
T3 Code가 Gmail, Drive, Calendar 접근 권한을 추가로 요청하지는 않습니다.
현재 T3 Code의 Gemini 제공자는 Google 로그인을 사용하며 Gemini API 키나 Vertex AI 인증 방식으로
전환하지 않습니다.

## Gemini CLI 설치

T3 Code는 Gemini CLI를 함께 배포하지 않습니다. T3 Code 서버가 실행되는 컴퓨터에 Gemini CLI를
설치하세요.

npm:

```bash
npm install -g @google/gemini-cli
```

Homebrew:

```bash
brew install gemini-cli
```

설치 후 같은 컴퓨터에서 다음 명령이 실행되는지 확인하세요.

```bash
gemini --version
```

T3 Code가 `gemini`를 찾지 못하면 **설정**의 Gemini 계정에서 **실행 파일 경로**를 지정하세요.
원격 환경을 사용하는 경우 브라우저나 휴대폰이 아니라 선택한 원격 환경의 컴퓨터에 CLI가 설치되어
있어야 합니다. 최신 설치 요구 사항은
[Gemini CLI 설치 안내](https://geminicli.com/docs/get-started/installation/)를 참고하세요.

## 첫 번째 Google 계정 연결

1. **설정**의 제공자 섹션에서 기본 Gemini 계정을 활성화하거나 **CLI 계정 추가**를 선택합니다.
2. 새 계정을 추가한다면 제공자로 **Gemini**를 선택하고 알아보기 쉬운 표시 이름과 인스턴스 ID를
   지정합니다.
3. **Gemini 계정 홈 경로**는 비워 두는 것을 권장합니다. T3 Code가 이 계정만을 위한 경로를
   자동으로 관리합니다.
4. 개인 Google 계정이라면 **Google Cloud 프로젝트**를 보통 비워 둘 수 있습니다. 회사·학교 계정이나
   조직의 Gemini Code Assist 라이선스를 사용한다면 해당 계정에 맞는
   프로젝트 ID가 필요할 수 있습니다.
5. Gemini 계정 카드에서 **Google로 로그인**을 선택합니다.
6. **Google 로그인 페이지 열기**를 누르고 사용할 Google 계정을 선택합니다.
7. Google이 표시한 인증 코드를 복사해 T3 Code에 붙여 넣은 다음 **Google 계정 연결**을 누릅니다.

연결이 끝나면 Gemini 계정 카드에 인증된 이메일이 표시됩니다. 이메일은 다른 제공자 계정과 마찬가지로
기본적으로 가려집니다.

회사·학교 계정에 필요한 프로젝트와 권한은
[Gemini CLI 인증 안내](https://geminicli.com/docs/get-started/authentication/)를 참고하세요. 프로젝트는
계정마다 다를 수 있으므로 전역 환경 변수가 아니라 해당 Gemini 계정의 **Google Cloud 프로젝트**에
입력하는 편이 안전합니다.

## 원격 환경에서 로그인

Google 로그인은 브라우저와 T3 Code 서버가 같은 컴퓨터에 있지 않아도 됩니다. Gemini CLI 로그인
프로세스는 선택한 환경에서 실행되고, Google 로그인 페이지는 현재 T3 Code를 보고 있는 브라우저에서
엽니다. 로그인 후 표시된 코드를 다시 T3 Code에 붙여 넣으면 서버 쪽 로그인이 완료됩니다.

계정 등록과 변경은 현재 데스크톱 앱 또는 웹의 **설정**에서 진행합니다. 모바일 앱에서는 웹이나
데스크톱에서 미리 연결한 Gemini 인스턴스를 선택해 작업할 수 있습니다.
Gemini 자격 증명은 서버 컴퓨터와 OS 사용자에 묶여 암호화되므로 환경을 다른 컴퓨터나 사용자로
옮겼다면 각 계정에서 Google 로그인을 다시 진행하세요.

- 인증 코드는 한 번만 사용할 수 있으며 T3 Code 설정에 저장되지 않습니다.
- 인증 코드를 다른 사람에게 보내지 마세요.
- 로그인 세션이 만료되었거나 코드를 거부하면 창을 닫고 Google 연결을 다시 시작하세요.
- 여러 환경을 등록했다면 **설정** 상단에서 실제 Gemini CLI가 실행될 환경을 먼저 선택하세요.

## Google 계정 여러 개 추가

계정마다 별도의 Gemini 제공자 인스턴스를 만드세요.

예시:

```text
Gemini Work      gemini_work
Gemini Personal  gemini_personal
```

각 계정을 추가할 때 **Gemini 계정 홈 경로**를 비워 두면 T3 Code가 인스턴스 ID를 기준으로 서로
다른 홈을 만듭니다. 그다음 각 카드에서 Google 로그인을 따로 진행하세요. 표시 이름과 구분 색상을
지정하면 새 대화의 모델 선택기에서 계정을 쉽게 구별할 수 있습니다.

사용자 지정 **Gemini 계정 홈 경로**를 지정한다면 계정마다 반드시 서로 다른 빈 경로를 사용하세요.
두 인스턴스가 같은 경로를 사용하면 Google 자격 증명과 Gemini 세션도 공유되어 계정이 격리되지
않습니다.

Gemini 계정별 홈에는 다음 상태가 함께 격리됩니다.

- Google 로그인 자격 증명
- Gemini CLI 설정
- Gemini 대화와 재개 상태

따라서 다른 Google 계정으로 작업하려면 새 대화를 만들고 원하는 Gemini 인스턴스를 선택하는 것이
안전합니다. 서로 다른 홈에서 시작한 기존 대화는 계정 사이를 자유롭게 전환하기 위한 용도가 아닙니다.

## 계정 제거와 다시 로그인

추가한 Gemini 계정은 해당 카드의 휴지통 버튼으로 T3 Code 설정에서 제거할 수 있습니다. 기본 Gemini
계정은 삭제하는 대신 비활성화하거나 기본값으로 초기화하세요.

계정 카드를 제거하는 동작은 T3 Code에서 그 제공자 인스턴스를 없애는 것뿐입니다. Google 계정의 앱
권한을 철회하거나 Gemini CLI가 저장한 자격 증명을 자동으로 삭제하지는 않습니다. 이 동작은 T3 Code가
자동 관리하는 홈도 디스크에서 지우지 않으며, 사용자가 지정한 외부 **Gemini 계정 홈 경로**도 절대
지우지 않습니다. 같은 인스턴스 ID나 같은 사용자 지정 홈으로 계정을 다시 추가하면 이전 로그인이 다시
사용될 수 있습니다.

인증이 만료되어 카드가 연결되지 않은 상태로 표시되면 같은 카드의 **Google로 로그인**에서 연결을 다시
진행하세요. 이미 연결된 카드를 다른 Google 계정으로 바꾸려면 **Google 계정 변경**을 선택하고 새 계정의
인증 코드를 제출하면 됩니다. 새 로그인이 성공해야 해당 인스턴스의 기존 자격 증명이 새 자격 증명으로
교체됩니다. 로그인 창을 취소하거나 인증이 실패하면 T3 Code가 이전 자격 증명을 복원하므로 기존 계정을
계속 사용할 수 있습니다.

기존 계정을 교체하지 않고 두 계정을 함께 유지하려면 **Google 계정 변경**을 사용하지 말고 별도의 Gemini
인스턴스를 추가하세요.

Google 쪽 권한까지 완전히 철회하려면 Google 계정의 보안 설정과 Gemini CLI의 인증 관리 기능을
사용하세요. T3 Code의 계정 제거 버튼은 권한 철회 기능이 아닙니다.
