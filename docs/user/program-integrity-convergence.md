# 프로그램 무결성 수렴

프로젝트에 등록한 프로그램은 여러 CLI 계정이 역할을 나눠 반복 점검하도록 설정할 수 있습니다. 이 기능은 한 계정이 자신의 수정을 스스로 승인하지 않도록 점검, 수정, 독립 검증 단계를 분리합니다.

수렴 루프는 다음 순서로 동작합니다.

1. 등록된 CLI가 코드, 설정, 테스트, 실행 경로와 오류 가능성을 점검합니다.
2. 다른 CLI가 발견 사항을 재현하고 수정합니다.
3. 수정하지 않은 CLI가 변경분과 검증 명령을 다시 확인합니다.
4. 실행 가능한 개선 사항이나 실패한 검증이 남으면 새 주기를 시작합니다.
5. 서로 다른 계정이 참여한 검증이 모두 통과하고, 개선 사항이 없다는 판정이 연속으로 확인되면 수렴 상태가 됩니다.

프로그램을 등록할 때 무결성 수렴을 켜고 프로젝트에 서로 다른 CLI 계정을 두 개 이상 역할로 배정하세요. 프로그램마다 집중 테스트, 타입 검사, 린트 같은 필수 검증 명령도 등록할 수 있습니다.

진행 중인 수렴 루프는 언제든 중지할 수 있습니다. 서버가 재시작되면 진행 상태와 활성 협업 실행을 다시 읽어 안전하게 이어갑니다.

수렴은 현재 코드와 등록된 검증 범위에서 더 이상 실행 가능한 문제가 발견되지 않았다는 운영 판정입니다. 모든 입력과 미래 환경에 대한 수학적 무결성을 보장한다는 뜻은 아닙니다. 새로운 코드, 의존성, 설정 또는 검증 명령이 추가되면 다시 시작해 최신 상태를 확인하세요.
