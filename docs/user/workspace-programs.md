# 프로젝트 프로그램 운영

T3 Code는 프로젝트마다 개발 서버, 작업 처리기, 로컬 API 같은 주요 프로그램을 등록하고 실행 상태를 추적할 수 있습니다. 프로젝트 운영 화면의 **주요 프로그램**에서 설정합니다.

## 프로그램 등록

**자동 발견 후보**는 프로젝트의 실행 작업, `package.json`, Docker Compose, Python, Rust 설정을 읽어 실행 후보를 제안합니다. 후보는 사용자가 **확인하고 등록**을 누르기 전에는 저장되거나 실행되지 않습니다. 자동으로 추정한 명령은 등록 전에 반드시 확인하세요.

직접 등록할 때 다음 항목을 설정할 수 있습니다.

- 프로그램 이름과 실행 명령
- 프로젝트 루트 기준 상대 작업 폴더
- T3 서버 시작 시 자동 실행 여부
- HTTP 또는 TCP 상태검사
- 오류로 취급할 로그 정규식
- 실행 시 전달할 환경 변수의 이름

환경 변수 값은 프로그램 정의에 복사하지 않습니다. 선택한 이름의 값만 프로그램을 시작할 때 서버 실행 환경에서 전달하며, 비밀로 보이는 값은 저장 로그와 오류 증거에서 가립니다.

## 실행 소유권

T3 Code는 프로젝트 운영 화면이 직접 시작한 프로세스의 PID만 관리합니다. 다른 터미널, 다른 프로젝트 또는 외부 도구가 시작한 프로세스를 찾아서 인수하거나 중지하지 않습니다.

서버가 종료될 때는 현재 서버가 직접 시작한 프로그램만 순서대로 중지합니다. 프로그램 삭제 시 해당 프로그램의 실행 기록과 장애도 함께 삭제됩니다.

비정상 종료 뒤 서버가 다시 시작되면 이전 PID를 다시 소유하지 않습니다. 남아 있던 실행 기록은 추적 중단으로 닫고 장애를 남긴 뒤, 자동 실행이 허용된 프로그램은 새 프로세스로 시작합니다. 중단된 AI 진단과 수정 후 재시작 검증도 저장된 장애 상태에서 복구합니다.

## 상태와 오류 감지

프로그램 카드에는 현재 실행 상태, PID, 시작 시각, 상태검사 결과, 최근 로그가 표시됩니다. 실행 기록과 장애는 재접속 후에도 유지됩니다.

장애는 다음 경우 생성됩니다.

- 프로그램을 시작하지 못함
- 프로그램이 예상하지 않게 종료됨
- 등록한 오류 패턴이 로그에서 발견됨
- HTTP 또는 TCP 상태검사가 설정된 횟수만큼 연속 실패함

같은 원인의 미해결 오류는 하나의 장애로 묶고 발생 횟수와 최근 증거를 갱신합니다. 이미 해결한 오류가 다시 발생하면 새 장애로 보고합니다.

## AI 진단과 수정

자동 AI 진단 권한이 켜져 있으면 장애마다 읽기 전용 진단 대화를 시작합니다. 진단 에이전트는 원인 후보, 영향, 수정 방향, 검증 절차를 정리하지만 파일을 수정하거나 프로그램을 제어하지 않습니다. 진단 대화는 일반 대화와 동일하게 모바일 알림과 바로가기를 사용할 수 있습니다.

실제 수정은 사용자가 오류 카드에서 **수정·검증 시작**을 눌러 명시적으로 지시한 뒤에만 시작됩니다. 수정 협업이 필수 검증을 통과하고 **수정 검증 후 자동 재시작** 권한도 켜져 있으면 해당 프로그램만 재시작합니다. 상태검사가 있으면 첫 정상 결과를 확인한 뒤 장애를 해결 처리합니다. 자동 재시작 권한이 꺼져 있으면 직접 재시작하고 결과를 확인한 뒤 해결 처리할 수 있습니다.

## 권한

**설정 → 권한 → 프로젝트 프로그램 운영**에서 다음 권한을 각각 제어합니다.

- 프로그램 수동 제어
- 최근 로그 수집
- 서버 시작 시 프로그램 자동 실행
- 오류 발생 시 읽기 전용 AI 자동 진단
- 사용자 지시로 수정하고 검증한 뒤 자동 재시작

자동 실행은 프로그램 자체의 자동 실행 설정과 권한 탭의 허용이 모두 켜져 있어야 동작합니다. 자동 재시작도 수정 검증을 통과한 경우에만 동작합니다.

## 상시 모니터링

장애가 난 뒤 반응하는 대신 프로그램을 계속 지켜보고 추세 이상까지 잡고 싶다면 [프로그램 모니터링 모드](./program-monitoring.md)를 켜세요. 같은 프로그램 등록과 상태검사를 그대로 사용합니다.
