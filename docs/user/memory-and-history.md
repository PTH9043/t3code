# 장기기억과 전체 이력

대화 원문은 로컬 데이터베이스에 남습니다. 자동 대화 기억이 켜져 있으면 매 요청에 현재 요청과 바로 전 사용자 발언에 관련된 기억, 같은 대화의 최근 발언을 추가합니다. 최근 발언은 최대 30개, 발언마다 최대 2,000자, 합계 약 16,000자로 제한하고 바로 전 사용자 발언을 우선합니다. 현재 메시지 이후의 발언은 이전 대화로 넣지 않습니다. 작업 중 새 단서가 드러나면 에이전트가 그 키워드로 다시 검색하고 필요한 원문을 확인할 수 있습니다. 사용자가 지정한 필수 지침은 검색어와 관계없이 유지합니다. 자동 대화 기억 설정을 끄면 검색된 기억과 최근 대화는 자동으로 추가하지 않습니다.

같은 출처의 기억에서 검색된 발췌 전체가 프로젝트 문맥에 이미 포함된 경우에는 그 발췌를 다시 보내지 않고 출처와 검증 상태를 유지합니다. 긴 원문의 일부 발췌인 경우에는 발췌 범위 밖의 원문을 별도로 확인해야 한다고 표시합니다. 발췌의 일부만 포함됐거나 출처가 다르면 기억을 그대로 전달하며 저장된 원문은 바꾸지 않습니다.

기억을 준비하는 데 오류가 나면 AI에 누락 사실을 전달하고 활동 기록에 남깁니다. AI가 이전 기억을 확인했다고 가정하지 않도록 상태와 원문을 다시 확인해야 합니다.

장기기억은 프로젝트와 현재 작업 폴더별로 구분합니다. 새 사용자 발언에는 확인된 작업 폴더를 기록하고, 자동 대화 기억과 원문 검색에서 같은 폴더의 기록을 사용합니다. 프로젝트 범위 지식은 프로젝트 루트에 적용하고, 폴더 범위 자료는 지정한 경로에 적용합니다. 사용자가 공용으로 지정한 기억과 필수 공용 지침은 별도로 유지합니다. 진행 중인 할 일과 작업 상태는 장기기억으로 확정하지 않습니다.

기존 대화와 수동 기억 중 저장 당시 폴더가 기록되지 않은 항목은 어느 폴더의 것인지 임의로 정하지 않습니다. 원문은 그대로 보존하지만 폴더별 자동 주입·검색·원문 조회에서 제외하며 누락 사실을 알립니다. 이 기록을 자동으로 모두 읽었다고 볼 수 없습니다. 이전 협업 결과와 지속 작업 상태 역시 폴더 범위를 확인하지 못하면 자동으로 넣지 않고 안내합니다.

일반 채팅에서 실제 존재하는 하위 폴더 경로를 하나 지정하면 그 폴더를 같은 대화의 후속 요청에서도 기억 검색 범위로 유지합니다. 다른 하위 폴더 하나를 지정하면 바뀝니다. 경로가 여러 개여서 구분할 수 없으면 이전 사용자 발언의 폴더가 확인된 경우 그 범위를 유지하고, 이전 범위도 확인되지 않으면 기억 누락을 알립니다. 대화를 되돌리면 남아 있는 대화에서 경로를 다시 찾습니다. 경로 표기가 인식되지 않거나 작업 폴더 확인이 실패하면 폴더별 기억을 임의로 선택하지 않고 AI에 누락 사실을 전달합니다. 자료의 범위를 바꾼 직후에는 기억 색인이 갱신되는 동안 이전 범위의 자료를 전달하지 않습니다.

사용자 결정·조건·정정과 출처가 명시된 작업 보고는 장기적으로 참고할 후보로 분류합니다. 단순한 응답도 원본 및 검색 기록은 보존하며, 분류는 표현에 근거한 규칙이므로 놓치거나 잘못 분류할 수 있습니다. 자료 검색에서는 일치한 후보 중 이런 신호를 우선하되 작업 보고는 미검증으로 표시합니다.

새 기록에는 원문 ID, 대화·턴 ID, 시각과 검증 상태가 붙습니다. 긴 대화는 원문을 보존하고 나누어 검색하며, 검색된 단어가 있는 부분을 발췌합니다. 사용자 발언과 에이전트의 작업 보고를 구분하며, 에이전트 보고에는 미검증 표시를 유지합니다. 주제별 정리는 원문 발췌와 출처를 모으는 방식입니다. 별도의 유료 모델을 호출해 사실 여부를 판정하지 않습니다. 현재 사용자 지시와 이후의 명시적 정정이 이전 기억보다 우선합니다.

에이전트는 `workspace_memory` 도구로 필요한 자료를 더 읽을 수 있습니다.

기억에서 직접 제외한 발언은 AI가 조회하는 기록 목록과 원문 조회에서도 제외합니다. 사용자가 직접 확인하는 원본 대화 기록은 보존합니다.

| 동작       | 용도                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| `status`   | 기억 준비 상태와 이력 색인 진행 위치 확인                                       |
| `search`   | 현재 폴더의 기억과 명시적으로 공유한 공용 기억 검색                             |
| `read`     | 현재 폴더 범위의 원문 조회. 긴 원문은 응답의 `next` 위치부터 계속 조회          |
| `history`  | 현재 폴더로 확인된 대화를 20개씩 조회. `next`가 있으면 계속 조회                |
| `export`   | 전체 대화에 다른 폴더나 미분류 기록이 섞일 수 있어 폴더 범위 AI 호출에서는 제한 |
| `remember` | 현재 폴더의 관례·결정·정정을 저장. 공용 저장은 사용자가 명시한 경우에만 사용    |
| `dream`    | 새 관찰을 주제별로 정리하고 기억 목차 갱신                                      |
| `forget`   | 활성 기억 검색과 주제 파일에서 제외. 원래 대화와 이전 버전 보관본은 유지        |

전체 이력이 필요한 감사·분쟁 확인·과거 결정 재검토에서는 폴더별 `history`나 일부 검색 결과만으로 전체 기록을 확인했다고 결론 내리지 않아야 합니다. 폴더를 확인하지 못한 예전 원문과 다른 폴더의 기록은 이 조회에 포함되지 않습니다.

모델을 바꿔도 기억은 같은 로컬 환경에 남습니다. 확인된 현재 폴더의 최근 대화 발췌와 추가 조회 방법을 새 모델에 전달합니다. 다른 폴더나 폴더 미확인 기록이 섞여 있으면 전체 압축 스냅샷은 자동으로 인계하지 않고 누락 사실을 표시합니다.

의미 검색을 켰다면 현재 범위에 속한 전체 청크를 작은 묶음으로 확인합니다. 최신 1,000개로 검색 범위를 제한하지 않습니다. 처음에는 일부 임베딩만 준비될 수 있으며 다음 검색에서 이어서 준비합니다. 임베딩 서비스를 사용할 수 없으면 키워드 검색 결과와 준비 상태를 표시합니다.

완료된 AI 실행 원문은 로컬 파일에서도 보관하고, 원문 조회가 필요할 때 읽습니다. 대화가 길어져도 완료된 원문 전체를 실행기의 메모리에 계속 복제하지 않습니다. 되돌린 턴의 보관 원문도 유지합니다.

오류 상태로 멈춘 AI 세션은 실제 작업, 백그라운드 작업, 승인 또는 사용자 답변 대기가 없으면 1분의 유예 후 정리합니다. 정리 확인은 1분 간격이며 대화 원문과 재개 정보는 보존합니다. 정상 대기 세션의 유휴 기준은 기존과 같은 30분입니다.

## 전역 답변 스타일과 대화방별 답변 스타일

**설정 → 일반 → 전역 모델 설정** 또는 대화 상단 **모델 설정**의 **전역 답변 스타일**에서 기본·간결·상세·친근·전문을 선택하고 말투, 길이, 설명 방식과 추가 지시를 정할 수 있습니다. 저장하면 모든 대화의 다음 요청부터 적용됩니다. 한 대화만 다르게 답하게 하려면 그 대화의 **모델 설정 → 이 방 답변 스타일**에 저장하세요. 대화에 저장한 스타일은 전역 스타일보다 우선하고 모델을 바꿔도 유지되며, **전역 스타일 사용**을 누르면 전역 스타일을 다시 따릅니다. 오케스트라는 작업자 역할을 유지하고 최종 답변에 스타일을 적용합니다. 모니터 비서는 답변 스타일을 우선하고 충돌하지 않는 범위에서 캐릭터 말투를 추가합니다. 현재 사용자 지시는 저장된 스타일보다는 우선합니다.

모바일에서는 대화 입력창 위의 **전역 답변 스타일**을 눌러 설정하고 저장할 수 있습니다. 한 대화만의 스타일은 대화 뷰어의 **이 대화의 답변 스타일**에서 정합니다. 진행 중인 답변은 그대로 유지됩니다.

### 답변 스타일에 따라 달라지는 화면

웹과 데스크톱에서는 적용 중인 답변 스타일이 화면에도 드러납니다. 모바일 앱은 답변을 일반 표시로 보여 줍니다.

- **모델 설정 버튼**: 간결·상세·친근·전문 스타일을 쓰는 대화는 상단 **모델 설정** 옆에 스타일 이름과 적용 범위(**전역** 또는 **이 방**)가 작게 표시됩니다. 창이 좁으면 이 표시는 숨겨집니다.
- **입력창 안내 문구**: 메시지를 바로 보낼 수 있는 상태에서는 입력창의 안내 문구가 스타일에 맞게 바뀝니다. 승인 대기, 계획 검토, 프로젝트 선택처럼 먼저 처리할 일이 있을 때는 기존 안내가 그대로 나옵니다.
- **대화 뷰어**: 최근 턴 정보에 **현재 답변 스타일**이 표시됩니다. 지금 설정된 스타일을 보여 주는 항목이며, 지난 턴에 어떤 스타일로 답했는지는 따로 기록하지 않습니다.

**전문** 프리셋을 고르거나 지시에 비서실장 역할 또는 `## [보고]` 형식을 적은 보고형 스타일에서는 다음이 더해집니다.

- **조언 카드**: 답변에 `## [비서실장의 조언]` 제목이 있으면 그 아래 내용을 본문과 구분된 카드로 보여 줍니다. 답변을 받는 중에도 카드 자리는 바뀌지 않고 내용만 이어서 채워집니다. 이 제목이 없는 답변은 평소처럼 표시됩니다.
- **상태 배지**: 본문의 `[확인 완료]`, `[합리적 추정]`, `[검증 필요]`, `[미확인]`, `[오류·반증]`, `[잠재력]`, `[현재 역량]`, `[검증된 성과]` 표기가 색으로 구분된 작은 배지로 보입니다. 코드 안에 적힌 표기는 바뀌지 않습니다.
- **대화 뷰어 요약**: 조언이 있는 답변은 **응답 결과** 위에 조언의 첫 문장과 상태 표기 개수(예: 확인 완료 3 · 검증 필요 1)가 항상 보입니다.

표시만 달라질 뿐 답변 원문은 바뀌지 않습니다. 조언 카드가 나타나면 본문 맨 위의 `## [보고]` 제목은 화면에서 생략되지만, 답변의 복사 버튼은 제목과 대괄호 표기를 포함한 원문을 그대로 복사합니다. 화면에서 글을 직접 선택해 복사하면 보이는 내용이 복사되고 상태 배지는 원래의 대괄호 표기로 복사됩니다. 스타일을 기본으로 되돌리거나 해제하면 이전 답변을 포함한 모든 답변이 곧바로 일반 표시로 돌아갑니다.

## 프로젝트 지식 위키

PC에서는 제어센터 첫 화면에서 원하는 프로젝트 옆의 **위키 열기**를 누르세요. 프로젝트 제어센터의 지식 목록에서 제목을 누르면 해당 문서가 전용 화면으로 열립니다. 문서 주소로 다시 열거나, 본문의 연결 문서와 이 문서를 참조하는 다른 문서를 따라갈 수 있습니다. 모바일에서는 프로젝트 운영 화면의 **지식 위키 열기**에서 문서를 찾고 읽을 수 있습니다.

본문에서 `[[문서 제목]]`을 쓰면 같은 프로젝트의 문서를 연결합니다. 제목이 같은 문서가 여러 개면 연결할 대상을 직접 고릅니다. 한 번 연결한 대상은 문서 ID로 기억합니다. 대상의 이름을 바꾸면 해당 문서를 참조하던 본문의 제목도 함께 바뀝니다. 아직 대상이 없는 링크는 문서에서 따로 확인할 수 있습니다.

에이전트 문서를 편집하면 사용자 편집본이 생깁니다. 원본은 다음 실행 결과를 계속 받으며, 편집본에서 원본을 열어 비교할 수 있습니다. 변경 이력에서는 저장된 개정을 골라 본문 차이를 볼 수 있습니다.

지식 목록의 **위키 관리**에서 후보 문서와 중복 문서를 확인하고, 여러 문서를 선택해 승격·보관·재분류할 수 있습니다. 병합할 때는 대표 문서를 직접 고릅니다. 병합한 다른 문서의 본문은 보존되며 대표 문서로 이동할 수 있습니다. 저장한 검색 조건은 같은 프로젝트에 연결된 기기에서 다시 사용할 수 있습니다.

**미사용**은 AI 요청에 이 항목을 넣은 기록이 0회라는 뜻입니다. 사람이 문서를 읽은 횟수는 이 지표에 포함되지 않습니다. 압축 통계는 원문과 저장 본문의 글자 수를 모두 확인할 수 있는 항목에서 계산합니다.

### 실습 · 같은 PDF의 판 바꾸기

가상 관측소의 인계표로 검색 결과와 원문이 언제 바뀌는지 확인해 보세요. 아래 파일은 이름이 모두 `관측소 인계표.pdf`입니다. 각각 다른 폴더에 저장하세요.

| 실습 파일                                           | 2쪽의 호출 부호 | 인계 시각 |
| --------------------------------------------------- | --------------- | --------- |
| [1판](<samples/pdf-revisions/v1/관측소 인계표.pdf>) | 유리나침반      | 18:00     |
| [2판](<samples/pdf-revisions/v2/관측소 인계표.pdf>) | 호박등불        | 19:30     |
| [3판](<samples/pdf-revisions/v3/관측소 인계표.pdf>) | 은빛망원경      | 21:00     |

1. PC의 실습용 프로젝트에서 대화에 **1판만** 일반 첨부해 메시지를 보내세요. 색인이 끝나면 프로젝트 제어센터의 **격리 RAG 검색**에서 `유리나침반`을 검색하고 결과의 **관측소 인계표.pdf** 제목을 누르세요.
2. 문서의 **PDF 버전**에서 **공개 버전 1**을 확인하세요. **새 버전 PDF**에서 2판 파일을 고른 뒤 **새 버전 올리기**를 누르세요. 파일 선택만으로는 등록되지 않습니다.
3. **공개 버전 2**가 되면 **공개 PDF 원문 보기**를 눌러 2쪽의 `호박등불`과 `19:30`을 확인하세요. **프로젝트 지식 검색**에서 `호박등불`로도 같은 문서를 찾을 수 있습니다.
4. 같은 문서에서 **새 버전 올리기**로 3판을 올리세요. **버전 3 색인 중**에는 공개 표시는 2이며, 검색과 공개 원문에서 확인할 수 있는 호출 부호도 여전히 `호박등불`입니다. 실습 파일은 두 쪽이라 중간 표시가 금방 지나갈 수 있습니다.
5. **공개 버전 3**이 보이면 `은빛망원경`을 검색하세요. 결과의 문서를 열어 원문 2쪽에서 `21:00`을 확인하세요. `호박등불`로 다시 검색했을 때 이 문서의 이전 본문은 나오지 않습니다.

**같은 이름으로 따로 보관하려면** 1판을 대화에 다시 일반 첨부해 보내세요. 별도 문서가 생겨 `유리나침반`과 `은빛망원경` 검색 결과에서 각각 **공개 버전 1**과 **공개 버전 3**을 열 수 있습니다.

색인 도중 서버가 중단되면 다시 시작할 때 저장된 지점부터 이어갑니다. **색인 실패**가 표시되면 현재 공개판은 그대로 읽을 수 있습니다. 오류 내용을 확인하고 **색인 재개**를 누르세요.
