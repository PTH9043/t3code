# AI별 RAG·캐시 활용

프로젝트 공통 지침을 앞에 유지하고 현재 작업을 뒤에 배치해 반복 문맥의 캐시 재사용을 돕습니다. 작업마다 필요한 지침은 그대로 반영합니다. 선택한 모델과 추론 수준은 이 기능 때문에 바뀌지 않습니다.

관련 문맥 모드에서는 작업과 관련된 근거를 예산 안에서 선택한 뒤 출처 순서로 배치합니다. 같은 근거의 검색 점수만 바뀌었을 때 입력 순서가 흔들리는 일을 줄입니다. 협업·회의의 공통 지침과 프로젝트 문맥은 실행 번호·라운드·실시간 대화보다 앞에 배치합니다. 필수 사용자 지침은 유지하며, 작업 인계에는 필요한 근거와 미해결 사항을 남깁니다.

## Claude 설정

설정 → 제공자 → Claude에서 일반 대화와 Claude 내부 하위 에이전트의 캐시 유지 시간을 각각 선택합니다.

- **Claude 기본 설정**: 현재 Claude 설정을 따릅니다. 기본 선택입니다.
- **5분**: 짧은 간격으로 이어지는 작업에 사용할 수 있습니다.
- **1시간**: 긴 간격의 반복 작업에 사용할 수 있습니다. 쓰기 비용이 늘 수 있어 실제 사용량을 비교해야 합니다.

변경은 새 세션부터 적용합니다. 환경 변수나 관리 정책이 우선할 수 있습니다. 앱에서 실행하는 오케스트라 작업자는 각각 일반 대화 설정을 사용하며, Claude 내부 하위 에이전트 설정과 구분됩니다.

## 세션 이어가기

같은 오케스트라 작업의 바로 다음 재시도는 이전 세션이 종료되어 있고 계정, 모델과 옵션, 작업 폴더, 권한이 같을 때 이전 대화를 이어갑니다. 조건이 바뀌면 새 세션을 사용합니다. Codex에서 이전 세션을 복원하지 못하면 새 세션에 대화 인계 문맥을 보냅니다.

이 재시도 경로는 Claude·Codex·Grok·Gemini·Cursor·OpenCode에 적용되며, OpenCode로 연결한 DeepSeek에도 적용됩니다. 제공자가 세션 복원을 지원하고 세션이 남아 있어야 실제로 이어집니다. OpenCode에서 세션이 없다고 확인되면 전체 작업 문맥으로 새 세션을 시작하고 복원 실패를 기록합니다. 인증·통신 오류를 빈 세션으로 숨기지는 않습니다.

세션 재개 여부와 캐시 적중은 다릅니다. 활동 기록은 세션 준비 상태를 보여주고, 캐시 적중은 제공자가 보고한 사용량으로 확인합니다. Codex에는 이 앱에서 임의의 캐시 유지 시간을 지정하지 않습니다.

## 문서 추출 재사용

설정 → AI 검색의 **동일 문서 추출 결과 재사용**은 기본으로 켜져 있습니다. 매번 파일 내용을 읽어 확인한 뒤 같은 프로젝트, 내용, 추출 조건의 정상 완료 결과만 재사용합니다. PDF·문서 등의 추출 작업을 줄이는 기능이며, AI가 읽는 입력 토큰 수의 감소를 의미하지는 않습니다.

**문서 캐시 새로고침**을 누르면 다음 요청부터 새로 추출합니다. 재사용을 끄고 설정을 저장할 수도 있습니다. 기존 대화와 추출 증거 파일은 지우지 않습니다. 실패하거나 일부만 추출한 결과는 캐시에 저장하지 않으며, 캐시 오류가 생기면 원본으로 다시 처리합니다. 저장 결과는 최대 7일, 128개, 총 32MB로 제한합니다.

## 실제 사용량 확인

사용량의 캐시 읽기·쓰기와, Claude가 보고한 경우 5분·1시간 캐시 쓰기를 확인합니다. 캐시 토큰은 입력 토큰에 포함되는 세부 항목이므로 총합에 다시 더하지 않습니다. **—**는 보고되지 않은 값이며 0이 아닙니다.

OpenCode·DeepSeek는 완료된 응답별 사용량을 원래 요청에 연결합니다. OpenCode의 입력은 캐시 읽기·쓰기를 별도로 보고하므로 앱에서 한 번만 합쳐 표시하며, 같은 응답을 다시 받아도 중복 합산하지 않습니다. Gemini·Cursor는 제공자가 표준 ACP 응답의 사용량을 반환하는 경우에만 기록합니다. 문맥 창 점유량을 소비 토큰이나 캐시 적중으로 간주하지 않습니다.

Codex를 재개했을 때 이전 누적 사용량이 전달될 수 있습니다. 앱은 처음 받은 값을 기준으로 삼아 과거 사용량을 다시 더하지 않습니다. 새 작업 전 기준값을 받지 못한 경우 첫 구간은 미확정으로 남습니다. Claude의 크레딧 부족 응답은 완료로 표시하지 않으며, 보고되지 않은 사용량을 0으로 만들지 않습니다.

캐시가 사용되어도 원래 문맥의 토큰 수는 그대로 집계될 수 있습니다. 실제 비용·지연 효과는 제공자의 과금 방식과 적중 결과에 따라 달라집니다. 이 기능은 토큰 소모를 만들기 위한 사전 호출이나 자동 캐시 예열을 하지 않습니다.
