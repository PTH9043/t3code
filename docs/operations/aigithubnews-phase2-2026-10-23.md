# 사진 끌어놓기 수정과 2차 업데이트 — 2026-10-23

사용자 요청: 탐색기에서 현재 대화·입력창과 왼쪽 프로젝트 목록으로 사진을 넣지 못하는 원인을 확인하고 수정한 뒤 2차 업데이트를 진행한다. 분리 후보에서 검증한 파일만 운영에 반영한다.

## 확인한 원인과 수정

- 운영 Electron 무결성 수준은 High(12288), 탐색기는 Medium(8192)이었다. Windows의 기본 OLE 드롭은 이 권한 경계를 통과하지 않는다. [Electron 재현 기록](https://github.com/electron/electron/issues/5243), [Windows 파일 드롭 메시지](https://learn.microsoft.com/en-us/windows/win32/shell/wm-dropfiles), [창별 메시지 필터](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changewindowmessagefilterex)를 확인했다.
- 운영 권한을 유지하고 메인 창에만 `WM_DROPFILES`와 파일 전송용 `WM_COPYGLOBALDATA`를 허용했다. 파일 수·크기·종류·읽기 결과를 검사하고 기존 이미지 압축·첨부 경로로 전달한다. 셸 명령과 자동 AI 실행을 연결하지 않는다. UAC·로그인 설정과 공용 실행 파일의 호환성 옵션은 변경하지 않는다.
- 대화와 작성창 외에 공용 제어센터의 프로젝트 목록, 기본 사이드바의 프로젝트 선택, 기존 사이드바의 프로젝트 이름에도 첨부 대상을 연결했다. 원격 프로젝트는 기존 업로드를 통해 파일 바이트를 해당 실행 환경에 보낸다.
- 같은 Git 저장소로 묶인 두 물리 프로젝트가 하나의 초안을 재사용·정리하던 동작을 재현했다. 파일 드롭으로 별도 초안을 만들 때 물리 프로젝트별 매핑을 사용해 원래 프로젝트의 미전송 사진을 보존한다. 모델·권한·질문·계획 설정은 기존 새 대화 경로를 따른다.
- 파일 읽기 도중 URL이 바뀌면 새 화면에 첨부하지 않고 다시 놓도록 안내한다. 드롭 위치는 배율과 화면 DPI를 반영하며, 파일을 놓는 것만으로 전송하지 않는다.
- 좁은 화면의 캡처에서 도움말·사이드바 버튼과 대화 탭이 겹치는 문제를 발견했다. 사이드바가 보이지 않을 때 탭 줄에 실제 제어 버튼의 공간과 높이를 확보하고, 390px 화면에서 버튼과 첫 탭의 경계가 겹치지 않는지도 검사한다.

## 2차 검색·기억 구현

- 버전이 있는 한국어 120문항을 추가했다. 의미 30, 정정 20, 시점 20, 프로젝트·폴더 범위 20, 제외·삭제 10, 긴 이력 10, 코드·버전 10이다. 개발용 92문항과 예약 검증용 28문항을 구분한다. 외부 비공개 정답 시험은 아니다.
- 실제 SQLite 검색 저장소와 최종 문맥 구성을 함께 실행한다. 키워드 모드와 실제 로컬 `bge-m3:latest` 모드를 분리하고, 색인 worker drain 이후 측정한다. Recall@5, MRR, 기대 근거 포함·금지 근거 제외·원문 출처 보존, cold/warm P50·P95, `o200k_base` 입력 토큰 추정을 저장한다.
- 수정 전에는 의미 검색이 찾아낸 근거를 문맥 구성의 키워드 조건에서 다시 제외했다. 검색 결과에 코사인 유사도를 선택 필드로 전달하고 기존 검색의 허용 기준을 그대로 사용한다. BM25/RRF 점수와 유사도를 혼동하지 않는다. 프로젝트·폴더·비활성·정정·유효 기간 필터는 계속 적용한다.
- 긴 기억의 의미 검색은 실제로 맞은 청크를 사용한다. 항목의 첫 페이지를 대신 주입하지 않는다. 원문 URL·기록 기준 시각·revision·근거 참조를 보존하고 같은 출처의 반복 청크에서 중복 근거 표기를 줄였다. 상대 날짜를 기록 시각으로 해석하고 계획을 완료 사실로 바꾸지 않도록 안내한다.
- 관련 문맥 모드의 기존 설정은 유지한다. 전체 문맥을 넣는 이전 모드의 기본값을 임의로 바꾸지 않는다. 취소·재시작·수락 불명·중복 사용량 처리는 기존 구현을 집중 회귀 검사한다. 결함을 확인하지 않은 부분을 새로 고쳤다고 보고하지 않는다.

## 검증과 운영 반영 기록

분리 후보: `D:/__NewAutoUsage-aigithubnews-20261023`. 이번 UI 시험의 새 데이터 홈은 `.t3/phase2-runtime`이며 운영 홈을 직접 사용하지 않았다. 운영 웹·백엔드·데스크톱은 `E:/NewAutoUsage`와 기존 관리자 실행기를 유지한다.

검증 자료는 운영 저장소의 `.t3/aigithubnews-phase2-20261023/`에 남긴다. 집중 테스트 251개와 웹·서버·데스크톱·계약의 범위별 타입 검사를 수행했다. 빌드와 변경 파일 lint를 확인했다. 승격·프로세스와 창 확인은 `promotion.json`, `production-visible-proof.json`, `backend-token-proof.json`, 최종 `completion.json`으로 확정한다. 입력 장치를 조작하지 않는 headless 렌더링과 숨긴 Electron의 네이티브 메시지 시험을 사용한다. 실제 탐색기에서 마우스로 끌어놓는 제스처 시험은 수행하지 않는다.
