# 검색 토큰·긴 작업 복구·문서와 스킬 개선 — 2026-10-24

사용자가 선택한 세 과제를 기존 T3 구조에서 개선했다. 외부 프레임워크나 기억 서버를 추가하지 않았다. 분리 후보는 `D:/__NewAutoUsage-aigithubnews-20261023`, 데이터는 기존 후보의 `.t3/phase2-runtime`이다. 운영 DB를 테스트에 사용하지 않는다.

## 검색 문맥 토큰

`relevant` 모드의 반복 안내와 구분 문구를 간결하게 정리했다. 현재 요청·필수 사용자 지침과 선택한 근거 본문·출처·기록 시각·revision은 유지한다. 기존 `standard` 모드와 프로젝트 설정을 바꾸지 않는다.

기존 한국어 120문항·예약 검증 28문항의 데이터셋을 유지했다. 실제 SQLite와 로컬 `bge-m3:latest` 검색을 사용했다. 단독 전후 실행은 시스템 부하에 따른 지연 차이가 커서, 같은 프로세스·같은 DB·같은 파생 벡터 캐시에서 질문별·회차별 전후 순서를 교대한 추가 비교를 실행했다. 준비 회차 뒤 각 구현에 4회·480관측을 기록했다.

| 항목                     |    이전 |    수정 |
| ------------------------ | ------: | ------: |
| 근거 조건 통과           | 120/120 | 120/120 |
| 예약 검증 조건 통과      |   28/28 |   28/28 |
| 입력 토큰 중앙값 추정    |     273 |     218 |
| warm P50                 |  3.19ms |  2.97ms |
| warm P95                 |  7.38ms |  7.42ms |
| 경계 위반·요구 근거 누락 |       0 |       0 |

토큰 중앙값은 약 20.1% 줄었다. P95 차이는 약 +0.5%이며 이 환경의 교대 비교에서 10% 상한 이내였다. 속도 향상을 일반화하지 않는다. 변경은 주로 고정 안내 55토큰을 줄인 것이어서 긴 근거가 많은 요청의 절감 비율은 더 작다. `o200k_base` 문맥 추정치이며 실제 provider 청구·전체 대화 사용량이 아니다. 답변 생성 모델을 호출하지 않았으므로 생성 답변의 정답률은 측정하지 않았다.

## 긴 작업 복구

이전 복구 장벽은 마지막 실패의 코드 fingerprint가 달라졌으면 전달 불명 검사보다 먼저 허용을 반환했다. 같은 목표의 입력 전달 여부가 불명확한 상태에서 checkout이 바뀐 사례로 이전 코드의 허용과 수정 코드의 거부를 재현했다.

- 미해결 `delivery_unknown`을 코드·요구 개정·이후 실패보다 먼저 확인한다. 원래 입력의 수락·진행 상태를 확인하기 전 같은 목표를 자동 재배정하지 않는다.
- 실패 후 한 번의 통신 재시도는 같은 코드 근거의 실패만 집계한다. 코드 근거가 없는 이전 기록은 보수적으로 유지한다.
- 과거에 저장된 `retryAllowed`가 true여도 현재 `delivery`가 accepted면 자동 재시도하지 않는다.
- 사용자가 직접 교체·인수·확정 요구 변경을 요청하면 불명확했던 이전 Main 지시를 대체 상태로 남긴다. 원래 메시지·명령·전달 기록을 유지하고 명시적인 새 지시를 사용한다.

SQLite에 저장한 불명 상태의 재조회, 재시작 뒤 checkout·요구 변경 후 실제 배정 API의 거부와 provider 실행 0건을 집중 테스트한다. 기존 취소·늦은 결과·중복 사용량·세션 복구·권한 보존 경로도 관련 회귀 대상으로 확인한다. 일반 대화 전체를 새 복구 엔진으로 바꾸거나 실제 외부 부수 효과의 정확히 한 번 실행을 보장하는 변경은 아니다.

## 문서와 스킬

프로젝트 스킬 `.agents/skills/t3-research-upgrade`에 실패 사례에서 출처·버전·검증·되돌리기로 이어지는 절차를 추가했다. `scripts/verify-research-upgrade.ts`는 후보 해시, 성공 검사 로그 해시, 복구 원본, 고정 commit과 비교 데이터셋의 일치를 읽기 전용으로 확인한다. 형식과 사용법은 [증거 기록 문서](../internals/research-upgrade-evidence.md)에 있다.

AKM의 피드백 기반 자산 개선, Context7의 버전별 출처, LangGraph의 체크포인트 규약, Promptfoo의 동일 평가셋 비교를 기존 조사에서 대조했다. 고정 출처는 이번 증거 manifest에 남긴다. 프로젝트용 스킬 파일을 추가하며 외부 서비스·계정을 자동 연결하지 않는다. 스킬이 파일에 저장된 것과 이미 열린 모든 AI 세션에 적용된 것은 구분한다.

## 적용 범위와 증거

검색·복구는 서버의 공통 처리이므로 웹·데스크톱·모바일에서 사용하는 기존 wire contract를 유지한다. provider 어댑터·모델·권한·질문하기·조건 확인·계획 모드를 바꾸지 않는다. 지속 작업실의 지원 provider 범위도 유지한다. 문서·스킬은 프로젝트 개발 도구이며 앱 사용자에게 새 설정을 요구하지 않는다.

증거 폴더는 `.t3/aigithubnews-phase3-20261024`다. 단독 전후 보고서와 `paired-baseline-hybrid.json`, `paired-candidate-hybrid.json`, `paired-comparison.json`, `recovery-before-after.json`을 보존한다. 집중 검사·검증 후 소스 일치·실제 운영 상태는 `tests-proof.json`, `types-proof.json`, `lint-proof.json`, `evidence.json`, `promotion.json` 및 배포 확인 파일로 구분한다. 운영 교체는 기존 관리자 실행기로 전체 web/backend/desktop을 비활성 표시하며 데이터 홈 `E:/NewAutoUsage`를 유지한다.

이번 과제는 전체 GitHub 전수 검토가 아니다. 기존 35개 README 판단과 100개 발췌 선별·24개 후속 실험 후보의 남은 범위는 그대로 유지한다.
