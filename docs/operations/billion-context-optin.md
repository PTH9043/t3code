# `billion-context` 선택적(Opt-In) 컨텍스트 압축 프록시 운영 런북

`ranxianglei/billion-context` (`bili`)는 CLI 에이전트와 LLM API 사이에 로컬 HTTP 프록시를 두어 초장문 다중 턴 세션의 토큰 사용량을 줄여 주는 **선택적(Opt-In) 실험 도구**입니다.

> [!IMPORTANT]
> **상시 기본 활성화 금지**: 검증된 벤치마크(MemoryAgentBench AR 197K)에서 **정적 원문 1줄 정확 복원(Exact Recall) 정답률이 69.0% → 27.0%로 하락**합니다.
> 따라서 정확한 코드 줄 번호·스택 트레이스·계약 스키마·수치 대조가 핵심인 기본 T3 Code 개발 세션에는 상시 적용하지 말고, **초장문 다중 턴 탐색·리서치·로그 대량 훑기** 세션에서만 사용자가 명시적으로 켜서 사용합니다.

## 1. 적용 기준 (언제 쓰고, 언제 쓰지 않는가)

| 작업 유형                                                  | 권장 여부          | 이유                                                                      |
| :--------------------------------------------------------- | :----------------- | :------------------------------------------------------------------------ |
| 초장문(300K~1M+ 토큰) 다중 턴 코드베이스 탐색·리서치       | **조건부 권장**    | ContextBench 다중 턴 탐색에서 비용 -58% 절감 및 1M+ 세션 생존율 개선      |
| 정밀 디버깅·단위 수치 대조·정확한 원문 인용·보안 감사      | **사용 비권장**    | 압축 과정에서 세부 1줄 원문 복원 정확도가 크게 떨어짐                     |
| T3 Code 기본 운영 세션 (이미 Handoff / `/compact` 사용 중) | **이중 압축 금지** | T3 자체 Handoff 압축과 `billion-context`를 동시에 켜면 정보 손실이 누적됨 |

## 2. 필수 안전 가드 (보안·네트워크·이중 압축 방지)

1. **루프백 바인딩 강제**: 프록시는 반드시 `127.0.0.1`(localhost)에만 바인딩하고 외부 인터페이스(`0.0.0.0`)에 절대 노출하지 않습니다.
2. **이중 압축 방지**: `bili` 프록시를 통해 CLI를 실행할 때는 해당 대화의 T3 자동 Handoff/강제 압축을 끄고, 반대로 T3 기본 대화에서는 `bili` 환경 변수(`ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL` 등)가 전역 오염되지 않도록 단일 명령 스코프에서만 실행합니다.
3. **라이선스 확인**: 외부 저장소(`ranxianglei/billion-context`)의 최신 라이선스 및 저작권 고지를 확인한 뒤 로컬 도구로만 사용하며, T3 Code 저장소에 소스 코드를 벤더링하지 않습니다.

## 3. 선택적 CLI 실행 예시 (단일 세션 스코프)

전역 환경 변수를 수정하지 말고, 필요한 터미널 세션에서만 래퍼 명령을 사용합니다.

```bash
# Claude Code 초장문 탐색 세션
bili claude

# Codex CLI 초장문 탐색 세션
bili codex

# Gemini / Antigravity 초장문 탐색 세션 (설치된 CLI 기준)
bili gemini
```

## 4. 장애·품질 저하 시 즉시 복구

- 에이전트가 방금 읽은 파일의 정확한 줄 번호·심볼명을 반복해서 놓치거나 환각을 보이면 즉시 `bili` 래퍼 세션을 종료하고 일반 T3 Code 세션(`/compact` 또는 새 스레드 + `progress.txt` 인계)으로 전환하세요.
- 프록시 포트가 남았는지 확인할 때는 전역 프로세스 패턴 종료(`pkill -f`)를 쓰지 말고 해당 터미널의 자식 PID만 종료합니다.
